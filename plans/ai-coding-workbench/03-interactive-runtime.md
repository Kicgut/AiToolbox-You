# Phase 3：会话内交互运行、续接与最小审计

> 状态：待审查（已有运行基础须重构，不代表本 Phase 完成）
> 更新时间：2026-08-01-23-20-00
> 依赖：Phase 1 的会话工作区、来源 identity/多来源状态和按需可读消息流
> 不包含：自动调度、多设备文件同步、原生 transcript 长期复制、一级运行中心、Workbench 自行替代原生权限机制。

## 目标

让用户在会话工作区内以 Codex 或 Claude 新建、续接或 Handoff，会实时看到可读消息流、工具摘要、原生审批与明确的回合完成状态。Workbench 只保存最小受控运行审计和必要状态；模型正文仍以新增到原生 JSONL 的内容为事实来源，随后由 Phase 1 的来源索引/按需读取显示。

## 现状证据

- 已有代码：`execution/codex_runtime.py`、`claude_runtime.py`、`runtime_coordinator.py`、`supervisor.py`、`approval.py`、`composer.py`、`runtime_stream.py` 及 Phase 3 测试已覆盖 fake/真实协议路径、进程监管、权限桥和取消等基础能力。
- 已核验的问题：Codex JSON-RPC 需要映射 `params.item`、`agentMessage/delta`、`item/completed` 与 `turn/completed`；只有 `turn/completed` 是一次输入的完成信号。此前 180 秒固定等待曾将有正确输出的回合误判失败，必须改为终态/超时语义分离。
- 边界冲突：`event_persistence.py`、RunCenter API/页面和完整 WebSocket 事件历史仍将运行事件当成长期开箱数据；这与最小审计和会话内体验不一致。

## 过时项（停止维护 / 删除目标）

- [ ] 废止一级“运行中心”路由、导航、独立列表和以原始事件标签页为主的使用方式。
- [ ] 废止把每条 run event、完整 stdout/stderr、raw JSON 和完整消息流永久写入 Workbench 数据库及用于 cursor replay 的设计。
- [ ] 废止把 `succeeded/failed` 仅由固定 180 秒等待结果决定的状态规则；原生终态、用户取消、进程错误和预算/超时必须区分。
- [ ] 废止跨工具 Resume / 伪造跨来源续接；只能同工具同一用户选择的原生来源 Resume，换工具必须 Handoff。
- [ ] 废止 Workbench 自建通用高权限授权层；高权限仅是工具专用 CLI 参数的显式选择，原生工具自己的审批仍由原生工具决定。

## 清理清单（需定位后逐项删除）

- [ ] 删除前端 RunCenter 页面、侧边导航、独立 run 详情、四类原始事件主视图和仅供其工作的 store/API；把必要状态迁入会话详情高级诊断、总览待处理和自动任务详情。
- [ ] 删除 `event_persistence.py` 及 `storage.py` 中完整事件/输出长期表、payload 外置文件、无限/长历史 cursor replay 与其清理任务；保留 Phase 0 定义的最小审计字段。
- [ ] 删除任何把 run 输出作为会话正文备用副本的读路径；会话刷新后应从原生文件展示正文。
- [ ] 删除所有针对 RunCenter、全事件持久化、旧 cursor 历史或独立详情的测试与 UI 文案，替换为会话内流和审计抽屉测试。
- [ ] 盘点并移除不再由新界面使用的 schema manifest/基线缓存；保留协议安全所必需的版本/能力快照，但不得存储完整 schema dump 或敏感本机信息。

## 修改清单（保留能力，收窄接口）

- [ ] 将 Runtime Coordinator 改为由会话 Composer 和自动任务调用的后台服务，而不是产品级“运行中心”；继续保留 Windows 进程树清理、argv、stdin、取消、超时和生命周期托管。
- [ ] 将 Codex/Claude adapter 统一为 `New`、`Resume`、`Handoff`、`cancel`、能力发现、事件规范化、原生审批转发；工具私有字段不得泄漏到通用 UI。
- [ ] 将 JSON-RPC / stream-json 映射转为短生命周期 UI event：增量可更新当前模型消息，工具事件可生成摘要，`turn/completed` 才令本次输入结束。
- [ ] 将 180 秒改为可配置的单次运行上限：到时先请求工具取消并记录 `timed_out`，但收到原生终态后按真实终态结算；不得把“没有新的流事件”本身判为失败。
- [ ] 将审批桥保留在当前会话的可读操作卡/高级诊断内，审批请求和 response 仅在运行期/最小审计范围保留，始终脱敏。

## 新增任务

### P3-01：最小运行身份、状态机与审计

- [ ] 定义最小 run 审计：run ID、发起来源（手动/任务）、工具/profile、native session ID、选定来源、动作、开始/结束、终态、取消/超时原因、能力快照、预算摘要、脱敏错误摘要和关联会话索引项。
- [ ] 定义状态机：`queued`、`starting`、`running`、`awaiting_approval`、`cancelling`、`succeeded`、`failed`、`cancelled`、`timed_out`；所有终态不可回退，重复取消/完成幂等。
- [ ] 建立“原生回合完成”与“子项/流增量完成”的独立测试，要求 `turn/completed` 或工具等价终态后才关闭 Composer 本次输入。
- [ ] 为 180 秒、进程退出、原生终态滞后、用户取消和网络断流分别定义可解释结果与 UI 文案。

### P3-02：安全 dispatch 与 native session 语义

- [ ] New：调用所选工具创建新原生会话，捕获其 native session ID 后交由 Phase 1 索引发现。
- [ ] Resume：仅允许同一工具、用户选定的可用来源；多来源/分叉会话必须先在高级诊断选择来源，禁止默认覆盖或合并。
- [ ] Handoff：从用户选择的消息/摘要生成新的另一工具原生会话，并明确显示为新会话，不冒充 Resume。
- [ ] 所有 prompt 经 stdin 或协议字段传递，命令为 argv 数组；项目目录必须是已登记工作区，防止 shell 注入和路径越界。
- [ ] 对 Codex/Claude 各自能力、参数、模型/profile 和高权限 flag 做 adapter 映射；不支持时在发送前给出可读拒绝原因。

### P3-03：会话内流式体验与诊断

- [ ] Composer 放入会话主区：未选会话默认 New，选中会话默认 Resume，换工具时显式 Handoff；输入前展示工具、profile、权限/预算摘要。
- [ ] 实现可读流：用户消息、模型增量、完成回复与一行工具摘要；模型/工具输出在 native 文件完成落盘后由来源刷新成为长期可读记录。
- [ ] 实现短暂断线重连与页面刷新恢复：通过当前 run 最小状态和原生文件读取恢复，不依赖永久 raw event replay。
- [ ] 在高级诊断抽屉按需提供来源、run 审计、协议警告、脱敏错误、审批状态和手动刷新；不得让 JSON 成为默认内容。

### P3-04：原生审批、取消、超时与资源管理

- [ ] 将原生审批请求/回复正确双向映射；工具不支持审批时禁用相关 UI，而不是伪造批准。
- [ ] 实现取消为一次请求 + 宽限期 + 受控进程树回退，并保证不会误杀用户自行启动的外部 Codex/Claude 进程。
- [ ] 运行上限到期后记录 `timed_out` 与取消结果；若工具明确成功/失败终态先到，则以真实终态为准。
- [ ] 启动、服务重启和关闭时 reconcile 最小运行审计；不重新执行未知旧请求，不持久化环境变量/凭据。

### P3-05：测试、真实验收与清理门

- [ ] 更新 `tests/ai_workbench/phase3/`：事件映射、回合完成、New/Resume/Handoff、同 ID 多来源、权限参数、取消、超时、审批、进程树和最小审计。
- [ ] 增加浏览器验证：一次输入只有一个明确“正在生成/已完成”生命周期；重复 delta 或 message item 不会被误显示为第二次完整回复。
- [ ] 在用户明确给出账号、工具、模型、prompt 和预算授权后，执行一次无害真实 New 与 Resume 验收；记录脱敏事件序号和终态，不保存正文/凭据。
- [ ] 确认旧 RunCenter/事件仓已不再被任何路由引用，完成删除前后 API、数据库大小和可读会话一致性检查。

## 退出标准

- [ ] 用户可在会话页可靠判断一次输入的开始、流式进行和结束；完成语义由原生回合终态而非固定等待或单一 delta 决定。
- [ ] New、Resume、Handoff 的边界不混淆，多来源/分叉不会导致自动续接或覆盖。
- [ ] Workbench 不长期存储完整运行事件或输出；原生文件仍是会话正文唯一事实来源。
- [ ] 独立运行中心已从导航和代码路径移除，必要诊断被放置到正确页面。
