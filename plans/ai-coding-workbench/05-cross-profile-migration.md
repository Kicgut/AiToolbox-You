# Phase 5：显式迁移、来源副本与设备交接

> 状态：待审查（高风险，须在实施前重新授权）
> 更新时间：2026-08-01-23-30-00
> 依赖：Phase 1 多来源与分叉语义；Phase 3 New/Resume/Handoff；Phase 4 任务摘要导出（如迁移任务）
> 不包含：持续同步、自动合并 JSONL、读取/控制 Cockpit、跨工具伪造 Resume、复制账户/凭据/项目代码。

## 目标

提供用户明确发起的一次性迁移/交接：导出 Workbench 轻量元数据、用户选定的原生会话文件以及可选的小型任务摘要；在目标设备或目录导入后作为独立来源副本显示。不会后台同步或合并 native JSONL；若两端随后各自 Resume，则标记为分叉并通过 Handoff 进行人工整合。

## 现状证据

- 当前没有 Phase 5 实现或测试目录。
- 旧计划以跨 profile 复制、备份、回滚、Cockpit 共存检测和可能的文件合并为中心，超出已确认的 source-first / owner-device 模型。
- 架构已确认：Cockpit Tools 仅共存，完全不接入；相同工具 + native session ID 的多个手动登记文件是多来源副本，不是需要 Workbench 自动合并的“会话家族”。

- [ ] 复用 Phase 4 的任务摘要模型（如已实现），仅导出用户选择且不含凭据、完整日志或正文的任务定义摘要。

## 新增任务

### P5-01：迁移包和用户确认

- [ ] 定义可审阅迁移清单：工具、native session ID、每个源文件的相对名称/哈希/字节数、轻量索引项、分组/收件箱、可选任务摘要及明确排除项。
- [ ] 在创建迁移包前展示选中范围、敏感内容警告、目标行为说明、预计大小和“导入后为独立来源副本”的确认文字。
- [ ] 明确排除 API Key、登录态、系统凭据、CC Switch/Cockpit 数据、完整事件投影、缓存、大型日志、项目代码和未选会话。
- [ ] 使用用户选择的位置创建包；默认不上传网络、不自动寻找其他设备。

### P5-02：导入、完整性与来源副本

- [ ] 实现导入前格式版本、哈希、路径穿越、重复 ID、磁盘空间和用户确认检查；解析失败不得影响既有索引。
- [ ] 导入原生文件时使用安全临时文件/原子落位，仅写入用户明确指定的 Workbench 管理导入目录或获授权的目标；任何外部原生 profile 写入均须单独逐文件确认。
- [ ] 导入后以通用目录登记和 Phase 1 扫描建立来源，不复制正文到数据库。
- [ ] 相同工具 + native session ID 显示“多来源”；默认最近完整来源；路径/哈希/差异仅在高级诊断抽屉可见。

### P5-03：分叉、交接与远程访问边界

- [ ] 检测共同来源在不同设备/目录后均有新增完整记录时，将其标为分叉；不自动合并、覆盖或推断胜者。
- [ ] 实现“交接”工作流：用户选择一个来源作为后续活动目标，Workbench 只记录选择/提示；源端不会被静默禁用或删除。
- [ ] 提供 Handoff 引导，将用户选取的摘要/消息在目标工具新建会话；这才是跨分叉或跨工具整合方式。
- [ ] 如提供远程访问，只允许认证后的浏览器访问单个所有者设备服务；不启用第二 scheduler、第二原生工具进程或后台同步。

### P5-04：安全、测试与删除规则

- [ ] 新建当前 `tests/ai_workbench/phase5/`：包清单、敏感排除、哈希失败、路径穿越、重复 ID、多来源、分叉、交接、部分失败与断电恢复。
- [ ] 验证全流程不读取/写入 Cockpit 或 CC Switch 目录，不复制凭据或项目代码，不执行原生工具。
- [ ] 对任何允许外部原生目录写入的可选路径，新增用户授权、精确目标展示、原子性和失败报告测试；未获批准则只支持导出/导入到 Workbench 管理目录。
- [ ] 记录每次实际迁移的清单摘要、大小、校验、来源状态和用户确认；不在日志中保存正文或凭据。

## 退出标准

- [ ] 迁移是一次性、可理解、用户确认的操作；不会形成持续同步或自动合并。
- [ ] 导入后会话仍由原生文件提供正文，Workbench 只有轻量索引和组织信息。
- [ ] 多来源与分叉安全可见，Resume/Handoff 的选择不被 Workbench 暗中替代。
- [ ] Cockpit 完全不参与数据、流程或测试前提。
