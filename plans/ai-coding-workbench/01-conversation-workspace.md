# Phase 1：会话工作区

> 状态：待审查（由原“只读会话中心”与“交互运行”合并重排）
> 更新时间：2026-08-03-12-13-27
> 创建时间：2026-07-22-00-03-54
> 适用范围：轻量会话索引、原生按需读取、会话组织、三栏会话页、New / Resume / Handoff、流式状态与最小受控运行审计
> 不包含：自动调度、显式跨设备迁移、账户/订阅余额连接器、Clash/Mihomo 流量采集、完整 transcript 或原始事件长期存储

## 合并与依赖说明

原 Phase 1 的“只读会话中心”和原 Phase 3 的“交互运行”共同交付同一会话工作区：用户在同一页面找会话、阅读原生消息、输入下一轮、判断原生回合完成，并在需要时查看诊断。将它们拆分会让页面、状态机和数据事实来源产生两套边界，因此合并为当前 Phase 1。

本阶段还提供 Phase 2 用量统计所需的稳定基础：`工具 + 原生会话 ID`、来源健康、项目登记与会话主项目归属。Phase 2 不重新创建第二套会话身份或归属模型。

以下重排前证据仅说明已有能力和已完成的清理，不构成当前合并 Phase 已完成的声明；所有仍需按目标架构验收的任务在本文件保持未勾选。

## 目标

建立以原生来源为先的会话工作区。Workbench 只持久化轻量索引、用户组织、项目归属与最小受控运行审计；Codex / Claude 原生 JSONL 始终是消息正文和原生会话身份的唯一事实来源。用户能够在一个三栏页面中安全地 New、Resume 或 Handoff，并以原生回合完成信号判断本次输入结束。

## 现状与历史证据

- 已有索引、扫描、监听、按需消息读取、分组/收件箱/最近、来源诊断与三栏页面的实现基础；历史验证显示扫描器不写入正文或 FTS。
- 已有 `execution/codex_runtime.py`、`claude_runtime.py`、`runtime_coordinator.py`、`supervisor.py`、`approval.py`、`composer.py`、`runtime_stream.py` 等运行基础，以及 fake/协议/进程监管测试。
- 已验证 Codex JSON-RPC 必须规范化 `params.item`、`agentMessage/delta`、`item/completed` 和 `turn/completed`；只有工具明确的原生回合完成信号可以结束一次输入。固定 180 秒等待不得把已完成回答误判为失败。
- 旧 `run_events`、`run_stream_cursors`、`run_artifacts` 的长期存储与独立 `/runs` 页面已在历史清理中移除；实时事件可作为短生命周期 UI 状态，但不再成为正文副本或永久回放仓。
- 历史浏览器验证仍不完整；必须在本阶段重新以当前三栏会话体验、单轮完成语义和真实来源读取为准验收。

## 过时项（停止维护 / 删除目标）

- [ ] 不再将完整原始 event、结构化消息、会话正文、raw JSON、完整 stdout/stderr 或常驻 FTS 写入 Workbench 数据库。
- [ ] 不再将“运行中心”、独立 run 列表或原始事件标签页作为产品入口；运行状态进入会话主区、高级诊断、总览待处理和自动任务详情。
- [ ] 不再保留 Conversation Family、Session Copy、跨 profile 自动合并、Cockpit 专用目录/状态检测或“会话副本”模型。
- [ ] 不再用固定 180 秒等待、单个 delta 或单个 item 完成作为 `succeeded` / `failed` 的唯一依据。
- [ ] 不支持跨工具 Resume 或伪造跨来源续接；换工具只能显式 Handoff，多来源必须由用户选择。
- [ ] 不建立 Workbench 自行决定的通用高权限层；高权限仅为工具专用 CLI 参数的显式选择，原生工具审批仍由原生工具决定。

## P1-01：轻量身份、来源与按需读取

- [ ] 建立或收敛会话索引、来源、组织、项目登记与归属表：只保存工具、原生会话 ID、来源路径指针/指纹、大小、mtime、offset、标题、最近摘要、最后活动、来源健康、项目关系与必要排序字段；不保存正文、raw event 或 FTS。
- [ ] 默认只读发现 Codex / Claude 来源与用户手动登记来源；禁止发现或读取 Cockpit、CC Switch、账户管理器目录。
- [ ] 以“工具 + 原生会话 ID”识别逻辑会话；同 ID 多来源显示一个逻辑会话与“多来源”状态，默认选择最近完整来源，禁止自动合并或覆盖。
- [ ] 处理 fingerprint、追加 offset、截断/旋转、完整 JSONL 行边界、未知记录、来源缺失与权限不足；不完整尾行延后处理，不得让单条未知记录损坏整个会话。
- [ ] 打开会话时从原生 JSONL 读取最近消息，向上滚动再按页读取；全文检索只按需扫描来源并返回短摘要，禁止常驻全文库或正文缓存。
- [ ] 提供目录变化约 2 秒防抖、活动页轻量刷新和低频兜底轮询；外部工具新建或续接会话后，列表和当前会话能安全更新。

## P1-02：项目归属、组织与可读会话界面

- [ ] 建立共享项目登记：用户确认根目录和 `project` / `workspace` 类型；`.git` 只建议候选，不自动登记或决定归属。
- [ ] 仅在已登记 `project` 根目录中按最长匹配将 `native_cwd` / `controlled_run` 自动归属；无 cwd、仅盘符、未匹配或仅位于 `workspace` 容器内的会话保持未归属。提供单会话和批量手动关联、解除与改关联的可审计界面。
- [ ] 实现一个主分组、收件箱与最近完整时间线三种互斥位置；解除收件箱或删除分组后，按原生最后活动时间回到最近。支持创建、改名、删除、拖放、筛选和搜索，不引入标签系统。
- [ ] 实现“全局导航 | 会话列表 | 可读消息主区”的桌面三栏；窄屏使用层级导航，不挤压三栏。主区默认显示用户消息、模型最终回复和一行工具摘要。
- [ ] 高级诊断抽屉按需提供来源选择、来源健康、原始协议、解析警告、受控运行审计和脱敏错误；JSON、事件列表和技术 payload 绝不作为默认阅读内容。

## P1-03：最小运行身份、状态机与安全 dispatch

- [ ] 定义最小 run 审计：run ID、发起来源（手动/任务）、工具/profile、native session ID、选定来源、动作、开始/结束、终态、取消/超时原因、能力快照、预算摘要、脱敏错误摘要和关联会话索引项。
- [ ] 定义幂等状态机：`queued`、`starting`、`running`、`awaiting_approval`、`cancelling`、`succeeded`、`failed`、`cancelled`、`timed_out`；终态不可回退，重复取消/完成必须安全。
- [ ] 将 Runtime Coordinator 收敛为会话 Composer 与后续自动任务调用的后台服务，保留 argv、stdin/protocol、超时、取消、进程树清理和生命周期托管，不再暴露独立运行中心。
- [ ] 统一 Codex / Claude adapter 的 `New`、`Resume`、`Handoff`、`cancel`、能力发现、事件规范化与原生审批转发；工具私有字段不得泄漏到通用 UI。
- [ ] prompt 必须经 stdin 或协议字段传递，命令采用 argv 数组；工作目录必须经过项目登记与路径边界校验。每个工具的模型/profile/权限 flag 由 adapter 映射，不支持时在发送前明确拒绝。

## P1-04：New、Resume、Handoff、流式体验与终态

- [ ] New：在选定工具创建新的原生会话，捕获原生 ID 后交给本阶段索引发现；未选会话时 Composer 默认 New。
- [ ] Resume：仅允许同一工具、用户选定且可用的原生来源；多来源/分叉先在高级诊断选择来源，禁止自动选择活动写入端。
- [ ] Handoff：由用户选择的消息或摘要创建另一工具中的新原生会话，清晰标注为新会话，绝不伪装成 Resume。
- [ ] 将 JSON-RPC / stream-json 规范化为短生命周期 UI event：delta 更新当前模型消息，工具事件生成摘要，`turn/completed` 或工具等价终态才结束本次输入。
- [ ] 将单次运行上限与终态分离：到期先请求取消并标记 `timed_out`，但若原生成功/失败终态先到则按真实终态结算；“一段时间没有新流事件”不能直接判失败。
- [ ] 在消息主区实现输入中、审批中、取消中、完成、失败、超时的可读状态；原生文件完成落盘后，长期阅读仍从来源文件读取，不依赖永久 event replay。

## P1-05：审批、取消、恢复与清理门

- [ ] 正确双向映射原生审批；不支持审批时禁用相关 UI，不伪造批准。审批内容仅在运行期/最小审计范围内脱敏保留。
- [ ] 取消采用一次请求、宽限期和受控进程树回退；不得误杀用户自行启动的外部 Codex / Claude 进程。
- [ ] 服务启动、重启和关闭时 reconcile 最小运行审计；不得重新执行未知旧请求，也不得持久化环境变量或凭据。
- [ ] 删除或停止维护仅服务于独立 RunCenter、永久事件仓、长 cursor replay、会话正文备用副本和旧 Cockpit/FTS 路径的代码、API、测试及文案。
- [ ] 删除前后检查 API、数据库大小、轻量索引和可读会话一致性；保留的运行审计不得重新长成事件/输出仓。

## P1-06：测试、浏览器验证与退出门

- [ ] 在 `tests/ai_workbench/` 的当前会话工作区测试域维护 fixture/合同：追加、半行、旋转、来源缺失、同 ID 多来源、分叉、分组移动、收件箱恢复、按需分页、搜索取消、项目最长匹配、手动归属和无正文投影。
- [ ] 覆盖事件映射、原生回合完成、New/Resume/Handoff、权限参数、审批、取消、超时、进程树、状态幂等与最小审计；未知协议必须安全降级。
- [ ] 浏览器验证一次输入只经历一个明确“正在生成 → 已完成/失败/取消/超时”生命周期；重复 delta 或 message item 不得显示为第二个完整回复。
- [ ] 只有用户明确批准账号、工具、模型、无害 prompt 与预算后，才执行真实 New / Resume 验收；证据仅记录脱敏事件序号、终态与边界结果，不记录正文、环境变量或凭据。

## 退出标准

- [ ] 会话正文、向上加载和全文命中均可证明来自原生文件按需读取；Workbench 只保存轻量索引、组织、归属与最小审计。
- [ ] 用户可在同一会话页可靠区分 New、Resume、Handoff，并以原生回合终态判断一次输入真正结束；多来源或分叉不会自动续接、覆盖或合并。
- [ ] 默认界面是可读连续对话；高级诊断可按需获得来源和协议证据，却不污染主消息流。
- [ ] 独立运行中心、永久事件/输出仓、完整 FTS/会话副本与 Cockpit 专用路径已不存在或不再由产品代码引用。
- [ ] 项目归属模型可被 Phase 2 直接复用，且不需要 Phase 2 再创建会话身份、正文投影或第二份映射表。
