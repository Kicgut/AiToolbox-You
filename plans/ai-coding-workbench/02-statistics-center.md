# Phase 2：用量统计、订阅额度与账户余额

> 状态：待审查（架构重基线后重写）
> 更新时间：2026-08-01-23-05-00
> 依赖：Phase 1 的原生来源发现、按需读取和轻量索引；官方连接器实施前须重新核验厂商文档
> 不包含：Clash/Mihomo 网络流量统计、读取 CC Switch 私密缓存/令牌、把外部账户数据当作会话事实来源。

## 目标

在不复制完整会话和原始事件的前提下，提供清晰分离的四类信息：原生会话可观察 Token、代理请求观测、订阅套餐额度、API 账户余额。总览只呈现四个重点卡片；完整明细留在用量统计页。CC Switch 仅在发现稳定、非敏感只读契约时作为独立可选卡片，不是连接器或依赖。

## 现状证据

- `usage.py` 已能从 native JSONL 容错提取 Token 字段，具备改为按需/轻量汇总的基础。
- `statistics.py`、`merge.py` 和 `storage.py` 当前围绕 `observations`、`usage_records`、`daily_rollups`、pricing snapshot、rebuild job 等重型持久投影运作；这些不能在目标架构下继续扩张。
- 现有 `tests/ai_workbench/test_phase2_*` 主要验证旧持久化、合并和重建语义，必须按新的数据来源与保留期重建测试口径。

## 过时项（停止维护 / 删除目标）

- [ ] 废止把每条 native usage / proxy observation 作为长期明细事件写入 Workbench 库的设计。
- [ ] 废止跨来源“合并成一个真实总 Token/真实总成本”的默认展示；不同观测口径只能并列，并明确不可相加。
- [ ] 废止将 pricing snapshot、复杂冲突组、长期重建任务作为首期核心数据模型；估算成本只能是可选、可解释的派生展示。
- [ ] 废止以 CC Switch 内部 SQLite schema、本机 token、账号、余额文本或私有缓存为统计来源的方案。
- [ ] 废止把代理流量页理解为 Token/模型/成本统计页；该页面继续只服务网络字节、连接与域名辅助视图。

## 清理清单（需定位后逐项删除）

- [ ] 盘点并删除旧 `observations`、`usage_records`、重型 daily rollup、复杂 merge/conflict、pricing snapshot/rebuild 表及其 API；若需小型日汇总，须以新契约重新建表而非保留兼容层。
- [ ] 删除 `statistics.py` 中依赖完整 event 投影的 rebuild/migration 调用链，以及前端对其进度、冲突、历史投影的展示。
- [ ] 删除 `compatibility/cc_switch.py` 中任何解析私有 schema、文件或凭据的实现和测试；保留“未安装/无稳定只读契约 = unavailable”的安全降级。
- [ ] 从用量 UI 删除会误导用户把代理观测、原生 Token、订阅窗口和余额相加的总数、图例或文案。
- [ ] 与 Phase 1 的旧库删除统一执行：不留下旧 usage 投影的长期备份、双读或兼容迁移路径。

## 修改清单（保留能力，切换数据边界）

- [ ] 将 `usage.py` 改为按需解析原生来源或从轻量增量摘要产生的可观察 Token 聚合，支持 `exact` / `estimated` / `unavailable` 质量标签。
- [ ] 将统计 API 改为按日期、工具、项目、模型等筛选的短期聚合接口；来源、质量、采集时间和不可用原因必须随数值返回。
- [ ] 将成本逻辑收窄为独立估算：定价版本、币种、公式和“仅估算”标签可见，不替代官方余额或账单。
- [ ] 将总览只接入四个摘要卡：今日 Token、近七日 Token、订阅套餐额度、API 账户余额与预警；卡片点击跳至用量统计页对应视图。
- [ ] 保持 `features/proxy-traffic-monitor/` 独立，只允许从用量页跳转说明，不共享或伪造 Token 数据。

## 新增任务

### P2-01：来源与数据合同

- [ ] 记录四类数据的独立合同、刷新策略、保留期、质量标签、失败原因和禁止相加规则。
- [ ] 实现会话 Token 聚合的最小缓存/日汇总（如确有性能需要），只保存聚合值、水位和来源版本，不保存完整事件或正文。
- [ ] 设计跨来源去重边界：同一 native 会话只能在同一原生读取口径内去重；代理观测、余额、订阅窗口永不与会话 Token 合并。

### P2-02：原生会话 Token 视图

- [ ] 从 Phase 1 已登记且健康的原生来源增量解析 Token；来源缺失、字段不支持或同 ID 多来源时显示明确质量与选择逻辑。
- [ ] 实现今日、近七日、按工具/项目/模型筛选和最近会话关联；不得因展示需要读取或永久保存完整正文。
- [ ] 实现用户主动刷新和后台低频刷新，避免浏览总览时对所有大 JSONL 重复全量扫描。

### P2-03：官方余额与订阅额度连接器

- [ ] 在实施前分别调研并记录 DeepSeek、阿里云、Kimi/Moonshot、GLM/OpenCode Go 等可用的官方文档、身份方式、调用频率、返回字段与用户授权范围。
- [ ] 仅为有稳定官方接口或用户明确可配置来源的厂商实现连接器；无官方、无授权或无法安全读取时显示 `unavailable`，不猜测余额。
- [ ] 把访问凭据留在操作系统凭据存储或用户指定安全机制，数据库仅存连接状态/上次刷新/脱敏标识，日志不得输出令牌或余额原文。
- [ ] 实现余额阈值预警与订阅窗口展示，分别标明时间窗、时区、数据源、更新时间和失效状态。

### P2-04：CC Switch 可选卡片

- [ ] 仅检测 CC Switch 是否安装及是否存在已确认的稳定非敏感只读公开契约；不扫描其账号、令牌、数据库或私密配置。
- [ ] 若其能安全提供订阅 5 小时/7 天窗口或 DeepSeek 余额的摘要，显示来源说明、刷新时间、不可用原因和“由 CC Switch 提供”；否则不显示数值。
- [ ] CC Switch 删除、升级、未运行或协议改变时，核心 Token/官方连接器功能保持可用。

### P2-05：UI、测试与证据

- [ ] 按视觉规范实现用量页分区：会话 Token、订阅/余额连接器、可选 CC Switch 卡片、数据质量/来源说明；代理流量只提供明确跳转。
- [ ] 为总览四卡、空态、过期、认证失败、限流、估算与多币种建立可访问的 UI 状态。
- [ ] 在当前 `tests/ai_workbench/` 下重写 fixture 测试：原生 Token 解析、聚合、来源分离、质量标签、连接器脱敏、CC Switch unavailable 和不相加约束。
- [ ] 记录性能读数、聚合容量、无凭据持久化检查和厂商接口验证证据；真实外部请求仅在用户给出账号、模型、预算和显式授权后进行。

## 退出标准

- [ ] 用户能区分会话 Token、代理观测、订阅窗口、API 余额和估算成本，界面与 API 均不会把它们相加。
- [ ] 所有原生 Token 可追溯到按需来源读取或小型聚合水位，数据库不保存完整 native usage/event。
- [ ] 官方连接器安全降级；CC Switch 永远是可选、无敏感读取的独立卡片。
- [ ] Phase 1/2 旧重型统计投影已按批准的删除报告移除，且没有兼容双读。
