# Phase 2：用量统计、订阅额度与账户余额

> 状态：待审查（会话工作区后的四类用量阶段）
> 更新时间：2026-08-03-12-13-27
> 创建时间：2026-07-22-00-03-54
> 适用范围：全局与项目级模型用量、CC Switch 只读聚合适配、原生 JSONL 历史/回退、订阅窗口、官方 API 余额与总览四卡
> 不包含：Clash/Mihomo 网络流量、CC Switch 凭据/设置/余额或订阅缓存、完整请求明细仓、完整会话投影、外部工具写入

> 依赖：Phase 1 提供的“工具 + 原生会话 ID”、来源状态、项目登记、项目归属和按需原生读取。Phase 2 只复用这些能力，不建立第二份会话索引或正文投影。

## 目标

实现并清楚区分四类目标：

1. 全局模型用量与估算成本；
2. 项目级模型用量与估算成本；
3. 订阅套餐窗口；
4. API 账户余额与预警。

全局和项目级必须展示同一套指标：总请求数、成功/失败请求数、成功率、真实消耗 Token、新鲜输入、输出、缓存创建、缓存命中/读取、缓存命中率、总成本/币种、延迟、TTFT，以及时间、工具/App、provider、模型、请求模型、来源和状态维度。缺少某字段时显示 `unavailable`，不补造数值。

## 现状与重基线

- 原先“CC Switch 仅为独立卡片、不得进入默认总计”的方案已废弃。CC Switch 在用户显式启用、版本和 schema 兼容时，是全局和近期项目用量的**优先只读聚合来源**，但永远不是 Workbench 的运行依赖。
- 原先“删除一切 CC Switch SQLite 读取”的完成项不再适用。新的实现必须仅按 allowlist 读取最小非敏感统计字段，以只读/query-only 模式运行；禁止读取任何凭据、provider 设置、订阅/余额缓存和请求正文。
- `proxy_request_logs` 的朴素求和不可用：实现必须复现已测试 CC Switch 版本的有效记录去重与缓存语义，防止代理记录与原生导入记录重复。
- CC Switch 的旧日汇总没有可靠的会话 ID / 项目路径，不能单独补建任意项目的全历史；项目首次登记仍需从原生 JSONL 建立日级历史基线。

## P2-01：统计合同与数据模型

- [ ] 为四类目标分别定义 API 合同、单位、时区、质量标签、覆盖范围、刷新时间、失败原因和不可相加规则。
- [ ] 定义统一指标合同与公式：缓存包含输入的来源先扣除缓存后得到新鲜输入；真实消耗 Token、缓存命中率、成功率均按架构公式计算，并保留口径版本。
- [ ] 建立项目登记、工作区容器、会话主项目归属和轻量 `project_usage_daily` 数据模型：根目录、类型（`project` / `workspace`）、归属来源、确认时间；日汇总保存项目、当地日期、工具、provider、模型、统一指标、来源、口径/适配器版本、覆盖状态和水位；禁止保存请求明细、raw event 或会话正文。
- [ ] 定义来源替换优先级：同一项目/日期/维度只能选一个带来源的结果；CC Switch 覆盖成功时替换同范围原生基线，绝不相加。

## P2-02：CC Switch 只读聚合适配器

- [ ] 实现用户显式启用、CC Switch 版本/schema allowlist、数据库只读/query-only 打开、锁定/不存在/不兼容安全降级和状态 API。
- [ ] 只读取时间、工具/App、provider、模型、请求模型、Token、成本、延迟、TTFT、状态、`session_id`、`data_source` 与必需口径字段；增加防回归断言，禁止 SQL 触及账号、配置、令牌、余额、订阅缓存或正文列。
- [ ] 以 fixture 重现 CC Switch 的有效记录过滤、代理优先去重、Codex 累计 Token delta 与 Claude 缓存字段语义；不以 `SUM(proxy_request_logs)` 取代这些规则。
- [ ] 实现全局时间趋势、provider/模型/工具分组和按需最近请求视图；最近请求不落入 Workbench 数据库。
- [ ] 记录适配器版本、CC Switch 版本/schema、最后成功读取、覆盖窗口和 `estimated` 数据质量。

## P2-03：项目级归属与原生回退

- [ ] 建立用户确认的项目根目录登记，并要求选择 `project` 或 `workspace`：前者可接收会话和项目统计，后者只组织子项目与容器内未归属用量。`.git` 只用于建议候选/类型，不作为项目存在或归属的前提。
- [ ] 原生 cwd / 受控运行 cwd 仅在已登记的 `project` 根目录中做最长匹配自动归属；无 cwd、仅工作区盘符或未匹配的会话保持未归属。位于 `workspace` 内但未匹配实际项目的会话标记该容器，绝不自动计入容器或其任一子项目。
- [ ] 实现“待归属会话”队列，以及单会话与多选批量手动主项目关联、解除和改关联。关联面板按需展示启动 cwd、标题、时间、首条/最近用户输入预览、最近摘要、显式路径证据、受控运行 cwd、Token/请求影响与候选项目；候选只排序，不自动确认。
- [ ] 每会话只允许一个主项目；项目页默认拆分原生/受控已确认与手动归属，并支持“仅原生/受控已确认”筛选。Token/成本质量与归属来源分别标示，`manual` 不得改变 Token 精度标签。
- [ ] 使用 Phase 1 的“工具 + 原生会话 ID → 项目”轻量索引，只将精确匹配 `session_id` 的 CC Switch 明细归属项目；缺 ID、未匹配或语义不明的行标记为未归属。
- [ ] 项目首次登记时从其原生 JSONL 建立全历史日级基线，正确处理 Codex `token_count` 累计/增量、Claude assistant usage 和缓存字段、子代理与重复记录。
- [ ] 后续以低频或数据库变更触发的 CC Switch 最近窗口刷新项目日汇总；CC Switch 缺失、不可归属或不兼容时，只增量解析变更原生文件回退。
- [ ] 明确并测试项目根目录变更、单体父项目、`workspace` 容器加项目 A/B/C、嵌套项目的最长匹配和用户确认、无 `.git` 项目、`E:\` 工作区会话、手动批量关联/撤销、多来源同原生会话、删除源文件、时区边界、晚安装 CC Switch、30 天明细过期和未归属用量。
- [ ] 记录首次全历史建立、近期 CC Switch 聚合与单文件增量回退的性能/容量证据。

## P2-04：订阅额度与 API 余额

- [ ] 仅为已有稳定官方文档并经用户授权的厂商实现余额/订阅连接器；当前优先 DeepSeek、Kimi/Moonshot、阿里云 BSS。没有正式契约的 OpenCode Go、GLM 等显示 `unavailable`。
- [ ] 将 Workbench 自己的授权存于操作系统凭据库或用户指定安全机制；数据库只保存连接状态、脱敏标识、最后值、刷新时间和阈值。
- [ ] 单独实现订阅窗口、余额和各自的 `stale` / 认证失败 / 限流 / 多币种 / 阈值预警状态；绝不使用 CC Switch 内部余额或订阅缓存替代官方来源。

## P2-05：界面、测试与验证

- [ ] 用量页按四类目标分区：全局模型用量、项目级模型用量、订阅套餐额度、API 余额与预警；总览四卡只跳转到对应筛选，不承担明细展示。
- [ ] 全局和项目级均展示统一摘要、趋势、provider/模型/工具分组、筛选、来源/覆盖说明和可访问的空态、加载态、过期态、错误态；项目级额外显示归属来源拆分与待归属入口。
- [ ] “最近请求”只在可用明细源时按需读取；高级说明明确它与 `代理流量`（Clash/Mihomo 网络字节、连接、域名）无关。

- [ ] 完成后运行本阶段计划中记录的测试、编译/构建和只读外部数据检查；将命令、结果、性能、容量与未覆盖边界写入本文件“执行证据”。真实外部请求仅在用户明确授权账号、模型和预算后进行。

## 退出标准

- [ ] 用户可以在同一页面清楚区分四类目标，且界面/API 不会将模型用量、订阅额度、账户余额和 Clash 网络流量相加。
- [ ] 全局与项目级模型用量拥有相同指标合同、口径说明和来源/覆盖标签；项目归属可区分原生/受控确认、手动和未归属，项目历史不会因 CC Switch 明细过期而丢失。
- [ ] CC Switch 只读适配器在兼容时显著减少近期聚合读取成本，在不兼容或不可用时完全降级到原生来源，不触碰敏感数据或外部数据库。
- [ ] Workbench 数据库只持有轻量项目日汇总和连接器状态，不持有完整请求日志、原生会话副本、raw event 或外部凭据。
