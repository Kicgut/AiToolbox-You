# UI-07：目标架构视觉设计实施

> 状态：待审查
> 更新时间：2026-08-01-23-40-00
> 依据：[视觉设计规范](../../docs/ai-coding-workbench-visual-design.md)、[会话工作区决策](../../docs/conversation-workspace-rethink.md)
> 不包含：后端数据合同变更、真实模型请求、外部工具写入、生成 Drawio/PNG 设计资产。

## 目标

把已确认的目标信息架构实现为桌面优先、可读优先的 Workbench SPA。重点不是装饰，而是把会话、运行、诊断、任务、用量和辅助功能放到用户最需要的位置：默认总览；会话使用三栏；原始协议仅在按需高级诊断抽屉；不再存在独立运行中心或运维一级页。

## 现状证据

- 当前前端已有会话中心、运行中心、用量、代理流量、设置等旧路由/组件基础，视觉和信息结构仍混有旧重型投影路线。
- 已确认目标导航顺序：`总览`（默认）、`会话`、`自动任务`、`用量统计`，分割线后 `代理流量`、`设置`。
- 文档可使用文本框图说明布局；未经用户明确请求不得新建 Drawio、PNG 或其他图像产物。

## 过时项（停止维护 / 删除目标）

- [ ] 删除“运行中心”和“运维”作为一级导航、默认落点或页面概念。
- [ ] 删除默认展示 raw event、JSON、诊断表和大段技术协议的会话/运行界面；它们只能在高级诊断抽屉按需出现。
- [ ] 删除旧总览中以未实现 Phase 占位卡、旧会话中心/运行中心入口或重型统计为主的布局。
- [ ] 删除将 CC Switch 放在代理流量页、将代理流量放进 Token 统计、或用外部工具状态占用核心会话阅读区的布局。

## 清理清单

- [ ] 盘点并删除旧 RunCenter route、导航项、页面组件、state、样式、测试选择器和构建资产引用。
- [ ] 盘点并删除依赖完整 event transcript/FTS/旧 usage 投影的 UI loading、虚拟列表和空态；以 Phase 1/2 的按需 API 替换。
- [ ] 清理过期的图示、截图断言和文案，使其不再承诺未批准的功能或旧页面顺序。
- [ ] 在不触及 `features/proxy-traffic-monitor/` 内部采集器的前提下，移除其与核心页面混合展示的旧样式依赖。

## 修改清单

- [ ] 将应用壳、路由守卫、面包屑/标题、快捷键和响应式布局改为新导航顺序与总览默认页。
- [ ] 将现有会话 UI 改为可读消息流优先，支持 Phase 1 的按需消息分页、来源状态、收件箱/最近/主分组和诊断抽屉。
- [ ] 将现有运行 UI 可复用的状态、取消、审批、连接状态组件迁入会话 Composer、会话高级诊断、总览待处理和自动任务详情。
- [ ] 将现有统计 UI 改为独立信息口径和数据质量展示，容纳官方连接器与可选 CC Switch 卡片，而不改变代理流量模块职责。

## 新增任务

### UI-07-01：应用壳与导航

- [ ] 实现固定全局导航与分割线，默认总览；桌面、窄屏、键盘焦点、屏幕阅读器标签和活跃态一致。
- [ ] 设计统一页面标题、工具/来源徽标、状态色、空态、加载态、错误态和数据新鲜度提示，避免仅用颜色表达状态。
- [ ] 建立可复用 token（间距、字号、边框、阴影、状态色、动画）并符合现有品牌与无障碍对比度要求。

### UI-07-02：总览

- [ ] 实现第一层四个水平统计卡：今日 Token、近七日 Token、订阅套餐额度、API 账户余额与预警；不可用时显示来源/原因而非伪造 0。
- [ ] 实现第二层待处理事项：运行中任务、失败自动任务、待确认操作；每项跳转至会话、任务或设置的正确位置。
- [ ] 实现第三层：左侧最近会话，右侧本地数据源状态；最近会话来自轻量索引，数据源状态不泄露本机敏感路径或凭据。

### UI-07-03：会话工作区

- [ ] 实现“全局导航 | 会话列表 | 对话主区”的三栏桌面布局：列表含新建、搜索、筛选、分组、收件箱与最近；主区有标题/工具标识、可读消息流和 Composer。
- [ ] 实现一个主分组、收件箱常驻和最近完整时间线的拖放/移动交互；删除分组或解除常驻后恢复到最近的时间位置。
- [ ] 实现消息阅读、工具摘要折叠、分页加载、来源健康、自动刷新和高级诊断抽屉；协议 JSON 不得成为默认阅读内容。
- [ ] 实现 Composer 的 New/Resume/Handoff 上下文、流式状态、审批/取消和回合完成反馈，接入 Phase 3 后端后不改变视觉语义。

### UI-07-04：自动任务、用量、代理与设置

- [ ] 实现自动任务的列表/编辑/运行记录/关联会话及总览待处理入口，接入 Phase 4。
- [ ] 实现用量统计的会话 Token、订阅/余额、可选 CC Switch 卡片、来源/质量说明及至代理流量的明确跳转，接入 Phase 2。
- [ ] 调整代理流量为分割线后辅助页，维持 Clash/Mihomo 网络含义和独立空态，接入 UI-06。
- [ ] 实现设置中的来源目录登记、刷新/索引状态、官方连接器配置、隐私/远程访问和任务默认项；不得出现 Cockpit 功能入口或凭据明文。

### UI-07-05：质量验证

- [ ] 为核心页面建立浏览器验证：默认总览、三栏会话、分组拖放、消息阅读/诊断隔离、Composer 状态、任务失败、统计不可用、代理空态、设置错误。
- [ ] 覆盖桌面和窄屏、键盘、焦点、减少动态效果、长会话、空数据、离线/错误以及中文文本溢出。
- [ ] 确认任何来自 native JSONL、外部连接器或诊断的敏感内容均不意外出现在标题、卡片、错误 toast、复制按钮或截图测试输出中。

## 退出标准

- [ ] 新导航和总览布局已完全替代旧 RunCenter/运维入口，页面之间的职责与架构一致。
- [ ] 用户可以把 Workbench 当作正常连续对话工具使用，而无需阅读原始协议；高级诊断仍可按需获得。
- [ ] 视觉实现与各功能 Phase 的实际数据合同一致，不用静态 mock 掩盖来源/权限/失败状态。
