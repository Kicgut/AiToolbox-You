# 会话工作台重构：讨论中的产品决策

> 状态：已确认产品决策
> 更新时间：2026-08-01-22-27-51
> 创建时间：2026-08-01-13-02-43
> 适用范围：会话工作区、总览、自动任务、用量统计、分组、原生会话读取及多设备协同的产品交互决策
> 不包含：具体 API、数据库迁移脚本、前端组件实现、真实模型请求或第三方工具写入

> 状态：讨论中，已确认条目仅作为本轮设计讨论的临时单一记录。
> 在全部决策完成前，不回填架构文档、阶段计划或实现代码。

## 1. 产品定位

AI Coding Workbench 是 Codex、Claude 等既有 AI 编程工具之上的统一工作台，不是第二套会话存储或 CLI 执行引擎。

目标：

1. 在同一工作台中展示多个 AI 编程工具的会话，提供跨工具、项目、日期、状态等筛选和检索。
2. 方便地在不同工具中新建会话、在同一工具中继续会话，以及显式发起跨工具交接。
3. 以网页端提供人类可读、连续对话式的展示，而不是以终端或原始协议为默认界面。
4. 增加定时控制和自动任务能力。
5. 在需要时提供运维能力：原始输入/输出、协议、诊断和运行记录可查，但默认折叠，不干扰正常对话。
6. 支持多设备查看、一次性复制/迁移和交接；不承诺多端同时写入同一个原生会话后的自动合并。

约束：

- 优先复用 Codex/Claude 原生文件及已有统计工具的事实数据。
- 不为方便展示而长期复制完整原生会话正文、raw JSON 或等价数据。
- 任何可能造成数百 MB 到数 GB 额外常驻数据的新设计，必须先说明收益、存储位置、保留策略和替代方案，并获得用户确认。

## 2. 已确认：信息架构

左侧实际一级导航定为：

```text
总览（默认页）
会话
自动任务（Phase 4）
用量统计

────────────

代理流量（辅助功能区；未来辅助功能放在此分割线下）
设置
```

说明：

- 不再保留一级导航“运行中心”。
- 不增加独立一级导航“运维”。
- 运维能力拆到总览、用量统计、设置、自动任务和具体会话详情的高级诊断抽屉中。

## 3. 已确认：会话页面布局

会话页面采用三栏加按需抽屉，而不是再进入单独的运行中心：

```text
全局导航 | 会话上下文列表 | 对话主区
                         └─ 高级诊断抽屉（按需从右侧打开）
```

实际布局：

```text
┌──────────┬──────────────────────────────┬────────────────────────────────────────────┐
│ 全局导航 │ 会话                         │ 当前会话                                   │
│          │                              │                                            │
│  总览    │ [+ 新建会话]                 │  标题 · Codex / Claude · 项目 · 状态       │
│  会话    │ [ 搜索会话、内容…       ]    │                                            │
│  自动任务│ [Codex] [Claude] [项目] [日期]│  用户消息                                  │
│  用量统计 │ ▼ 用户分组 A                 │  模型回复                                  │
│          │   • 提起到分组的会话          │  工具活动摘要（可展开）                    │
│          │                              │                                            │
│ ──────── │ ▼ 收件箱（常驻）             │                                            │
│  代理流量│   • 提起但暂不归组的会话      │                                            │
│  设置    │                              │                                            │
│          │ 最近                          │                                            │
│          │   • 未提起的会话，按时间排序  │                                            │
│          │   • ……向下滚动继续浏览历史    │                                            │
│          │                              │  [New / Resume / Handoff] 输入框           │
│          │                              │                         [高级诊断 ↗]       │
└──────────┴──────────────────────────────┴────────────────────────────────────────────┘
```

会话上下文列表：

- 位于全局导航右侧，只在“会话”页面出现；可收起、可调整宽度。
- 所有 Codex/Claude 会话按最近活动时间混排。
- 顶部提供新建、搜索、工具/项目/日期/状态筛选。
- 会话项展示：工具标识、首次用户输入标题、最近内容摘要、时间和状态。
- 支持用户分组、收件箱和最近历史流。
- 搜索和筛选覆盖全部会话；分组、收件箱和最近是互斥的侧栏位置，不产生副本。

对话主区：

- 未选择会话时即为新建会话。
- 选择会话后，以用户消息、模型回复和工具摘要组成可读消息流。
- New、Resume、Handoff 是输入框附近的明确动作，不再是一级页面跳转。

高级诊断抽屉：

- 默认关闭。
- 显示原始事件、协议 payload、stderr、工具调用、审批、运行状态和进程诊断。
- 仅用于排障和审计；普通对话界面不以原始输出为主体。


## 4. 已确认：会话操作语义

| 动作 | 语义 |
|---|---|
| New | 在选定工具中创建新的原生会话。 |
| Resume | 在同一工具、同一原生会话中继续，保留原生上下文。 |
| Handoff | 从当前会话生成可审阅的上下文摘要或用户选定消息，在另一工具创建新的原生会话；必须明确标注为跨工具新会话，不能伪装成 Resume。 |

## 5. 已确认：轻量索引与原始文件优先

Codex/Claude 原生 JSONL transcript 是完整会话正文的唯一事实来源。Workbench 长期只保存轻量索引和自己的控制/组织数据：

- 工具 profile、原生会话 ID、原始路径、文件大小/修改时间/内容指纹/解析偏移；
- 首次用户输入标题、最近内容摘要、最后活动时间、工具/项目/状态等筛选字段；
- Workbench 分组关联；
- 受控 Run、审批、取消和必要审计记录；
- 明确允许的小型、可清理的脱敏缓存。

默认扫描：

- 建立并增量更新轻量元数据索引；
- 不持久化每条原生 event、完整 raw JSON、完整结构化 JSON 或全文 FTS 副本；
- 不复制、不移动、不改写 Codex/Claude 原生文件。

自动更新：

| 场景 | 行为 | 预期延迟 |
|---|---|---:|
| 外部 Codex/Claude 新建或继续会话 | 监听原生会话目录，只刷新发生变化文件的轻量索引。 | 约 2–5 秒 |
| 正在查看的会话有外部新内容 | 页面提示来源有新内容；可自动追加底部消息或由用户点击刷新。 | 约 2–5 秒 |
| 原生文件仍在写入 | 2 秒防抖，只读取完整 JSONL 行；半行不会进入会话列表。 | 文件稳定后 |
| 目录监听不可用或漏事件 | 后备轮询只比较路径、大小和修改时间；仅变化文件继续读取。 | 最迟 30 秒 |
| 打开会话页或用户点击刷新 | 立即进行一次轻量目录发现。 | 即时 |

自动更新只改写轻量字段（会话标识、路径、文件指纹/偏移、标题、最近摘要、最后活动时间、项目/工具/位置和来源状态），不建立完整 event、raw JSON、结构化 JSON 或常驻全文副本。

全文检索：

- 用户主动搜索时，按需扫描原始文件并返回命中片段；
- 不建立常驻全文副本；
- 将来若引入缓存，必须设置大小上限、保留期、清理入口和存储成本说明。

打开会话：

- 直接从原始 JSONL 读取并解析；
- 首屏展示最近 50 组用户/模型消息；
- 向上滚动时继续按需读取更早消息；
- 原始来源缺失时保留索引卡片并明确标记“来源暂不可用”，不伪造历史正文；
- 受控运行中新事件直接追加到当前页面，原生文件最终成为会话事实来源。

## 6. 已确认：标题、摘要与分组

标题和摘要：

- 标题：首次用户输入的第一行或前 48–60 个可见字符。
- 最近内容：最近一条用户或模型消息的前 80–120 个字符。
- 两者均为 Workbench 轻量索引字段，不改写原生文件。

分组和侧栏位置：

- 分组是 Workbench 专有组织数据。
- 第一版一个会话最多位于一个用户分组、收件箱或最近历史流中的一个位置。
- 拖入分组只更新“会话 ID ↔ 分组 ID”的轻量关联。
- 新建或扫描到的会话默认进入最近历史流，按原生最后活动时间排序。
- 拖入用户分组或收件箱时，会话从最近历史流提起；从分组移出或解除收件箱常驻时，按原生最后活动时间回到最近历史流的正确位置。
- 不移动、复制或改写原生文件，不改变 Codex/Claude 原生会话归属。
- 多标签作为后续增强，不进入第一版。

侧栏位置与搜索范围：

| 位置/范围 | 含义 | 是否与其他侧栏位置重叠 |
|---|---|---|
| 搜索 / 筛选 | 跨所有已发现会话查询，不是一个重复的固定列表区。 | 不适用。 |
| 用户分组 | 用户主动提起并组织的会话。 | 否；一个会话仅有一个主分组。 |
| 收件箱（常驻） | 用户主动提起、暂不归入用户分组的会话。 | 否；解除常驻后回到最近历史流。 |
| 最近 | 默认完整历史时间流；承载所有未被提起到分组或收件箱的会话，向下滚动可继续浏览。 | 否。 |

收件箱是常驻位置，最近是默认时间排序位置。最近不是“只保留 N 条”的快捷入口；未分组、未常驻的 Codex/Claude 会话会一直在其中，按原生最后活动时间排序。

## 7. 已确认：对话消息流展示

主区采用市场和厂商主流对话工具的心智模型：可读消息流为默认，运维与原始协议为按需能力。

| 内容 | 默认展示 | 展开后 | 高级诊断抽屉 |
|---|---|---|---|
| 用户消息 | 始终直接显示。 | — | 原始 native 记录可查。 |
| 模型最终回答 | 始终直接显示。 | — | 原始 native 记录可查。 |
| 模型显式计划、说明或过程性文字 | 归入当前回答的“过程”可展开块。 | 显示该工具明确输出的可读文字。 | 原始事件可查。 |
| 工具活动 | 一行安全摘要，例如“读取 1 个文件 · 无修改”。 | 命令、路径、输出摘要和审批结果。 | 完整 payload、stderr 和大输出 artifact。 |
| 错误/取消/超时 | 紧凑、可读的状态提示。 | 原因和可恢复操作。 | 原始诊断可查。 |

- 不尝试提取、生成、持久化或展示模型未显式提供给用户的隐藏内部推理。
- 原始协议 payload、stderr、完整工具输出不占用正常对话主区。
- 同一原生 turn 的多个流式 delta 归并到对应的消息项；`turn/completed` 与 Workbench 终态共同表示该次输入结束。

## 8. 已确认：输入框与会话动作

不再使用容易误操作的 `New / Resume / Fork` 模式下拉框。输入框根据当前是否选中会话呈现明确动作：

| 当前状态 | 输入框默认动作 | 工具/Profile 规则 |
|---|---|---|
| 未选择会话 | 新建会话 | 用户选择 Codex 或 Claude；默认上次使用的可用 profile。 |
| 已选择 Codex 会话 | 继续此会话 | 锁定到该 Codex 原生会话和其 profile。 |
| 已选择 Claude 会话 | 继续此会话 | 锁定到该 Claude 原生会话和其 profile。 |
| 希望换工具 | 交接到… | 打开确认面板，选择目标工具和要携带的摘要/消息；创建明确标注的跨工具新会话。 |
| 希望不继承上下文 | 新建 | 创建独立新会话。 |

- 已打开原生会话时，发送默认执行同工具 Resume。
- 跨工具不能伪装为 Resume，必须显式执行 Handoff。
- 输入框附近保留当前工具、profile、权限/预算摘要和可读确认，不要求用户跳转到独立运行页面。

## 9. 已确认：总览页面的布局、信息边界与操作入口

总览沿用现有页面的视觉骨架和右上角全局操作区；不为增加统计而新增第二套页面结构，也不在此放置“新建会话”功能块。页面仅替换每一层承载的内容：

```text
┌──────────────────────────────────────────────────────────────────────────────────────────┐
│ 本地 AI 开发工作台                                                                         │
│ 早上好，开发者                                  [全局搜索待开发]  [通知] [账户]            │
│ 会话、自动任务、统计与流量监控的本地工作入口。                                             │
├──────────────────────┬──────────────────────┬──────────────────────┬──────────────────────┤
│ 今日 Token           │ 近七日 Token         │ 订阅套餐额度         │ API 账户余额与预警  │
│ 数值 / 同比或环比    │ 数值 / 趋势           │ 最临界套餐与周期      │ 最低余额 / 风险数    │
│ → 用量统计           │ → 用量统计           │ → 用量统计           │ → 用量统计           │
├───────────────────────────────────────────────────────────────┬──────────────────────────┤
│ 待处理事项（主要内容区）                                        │                          │
│ 运行中的任务 · 失败自动任务 · 待确认操作 · 最近异常             │ 操作项状态、影响与跳转    │
│ 空状态：当前没有需要处理的事项                                  │                          │
├───────────────────────────────────────────────────────────────┼──────────────────────────┤
│ 最近会话（左）                                                  │ 本地数据源状态（右）      │
│ 最近活跃的 Codex / Claude 会话；点击直接进入会话工作区          │ Codex、Claude、统计来源    │
│ → 查看全部会话                                                  │ 最近同步时间、可用性、异常 │
└───────────────────────────────────────────────────────────────┴──────────────────────────┘
```

### 各层职责

| 页面层级 | 数量与比例 | 职责 | 不承担的职责 |
|---|---:|---|---|
| 第一层统计卡 | 4 个等宽卡 | 给出跨页面最重要且可行动的“现在”指标；每卡链接到用量统计的对应筛选视图 | 不展示厂商明细、历史明细或诊断原文 |
| 第二层待处理事项 | 1 个横向主卡 | 汇总必须处理的运行中任务、失败自动任务、待确认操作及异常；按紧急程度排序 | 不是运行历史列表，也不是独立运行中心 |
| 第三层最近会话 | 左侧宽卡 | 提供继续工作的快捷入口，显示少量最近活跃会话及其工具、标题、最新摘要与时间 | 不复制会话正文；完整列表在“会话”页 |
| 第三层本地数据源状态 | 右侧窄卡 | 显示原生会话来源、统计连接器的健康状态、最后同步时间与可恢复异常 | 不把原始事件、日志或凭据暴露在总览 |

### 第一层四张统计卡

| 卡片 | 主值 | 需要时的次级信息 | 数据状态规则 |
|---|---|---|---|
| 今日 Token | 当地自然日的汇总 Token | 相比前一日的趋势；覆盖的工具数量 | 没有可核验来源时显示“暂无数据”，不显示估算为零 |
| 近七日 Token | 最近连续 7 天汇总 Token | 简短趋势或日均值 | 与用量统计共用同一口径，点击进入七日筛选 |
| 订阅套餐额度 | 当前最临界的套餐窗口及剩余/已用比例 | 厂商、窗口（如 5h / 7d）和刷新时间 | 只展示已授权、可核验的来源；未接入显示“未连接” |
| API 账户余额与预警 | 最低余额或预警数量 | 受影响厂商与阈值 | 不可获取余额时明确显示“暂不支持/未连接”，绝不把未知当作零余额 |

### 数据与交互原则

- **总览是入口，不是第二套统计页。** 四张统计卡只给摘要；厂商、模型、项目、时间窗口、原始计量和配置统一在“用量统计”。
- **总览是待办优先，而非运行优先。** 第二层只保留需要用户注意或操作的事项；已完成的运行记录不占用该区域。
- **会话直接可继续。** 最近会话只作为进入会话工作区的入口；点击后进入人类可读的对话主区，而非原始事件页。
- **数据源状态以可恢复性为中心。** 显示“可用、同步中、需要重新授权、来源不可用”等状态和最后成功同步时间；详细错误进入设置或会话高级诊断抽屉。
- **同一事实只保留一个权威来源。** Token 口径来自现有统计数据；套餐额度与账户余额由各厂商的独立只读连接器提供。总览只消费汇总结果，不复制完整账单、原始响应或凭据。
- **未知必须可见。** 不支持、未连接、授权失效和数据过期必须与正常数值清晰区分，并给出对应的设置或查看入口。
- **账户数据后续逐厂商核实。** DeepSeek、阿里云、OpenCode Go、Kimi、GLM 的余额或套餐数据，只有在确认其官方可用接口、授权方式、刷新限制和返回口径后才接入；不通过网页抓取或保存明文密钥实现。

## 10. 已确认：分组的跨设备携带

- 分组定义，以及“原生会话 ID → 主分组 / 收件箱位置”的关联，属于 Workbench 的轻量组织数据；不写入、不移动、不修改 Codex/Claude 原生会话文件。
- 默认不做后台自动同步，也不承诺多个设备同时编辑同一组元数据后的自动合并。
- 用户主动执行迁移时，分组定义和关联随轻量元数据包显式导出、导入；原生会话正文仍由用户按需要复制或迁移。
- 目标设备按“工具 + 原生会话 ID”匹配关联。若原生来源尚未被发现，关联保留为“等待来源”，不得伪造会话内容；之后扫描发现来源时自动恢复关联。

## 11. 已确认：删除分组的安全语义

- 删除操作只删除 Workbench 中的分组定义，不删除会话索引、受控运行记录或 Codex/Claude 原生会话文件。
- 删除前应显示受影响会话数量并进行确认。
- 分组内所有会话在确认后自动回到“最近”完整时间流，按各自原生最后活动时间恢复到正确位置。
- “收件箱（常驻）”不是用户可删除的分组；解除单个会话常驻后，同样回到“最近”。

## 12. 已确认：分组排序

- 用户创建的分组按侧栏内的手动拖拽顺序排列；排序值属于可随轻量元数据包迁移的 Workbench 元数据。
- 新建分组默认追加到所有现有用户分组之后。
- “收件箱（常驻）”与“最近”始终位于用户分组之后，位置固定，不参与拖拽排序。
- 组内会话不另设手动排序；按照各自原生最后活动时间排列，以便继续工作时自动上浮。

## 13. 已确认：分组创建

- 用户通过会话侧栏的“+ 新建分组”创建空分组，再将会话拖入其中；不按项目、工具或来源自动创建用户分组。
- 分组名称去除首尾空格后不能为空；同一 Workbench 中不允许重复名称，避免侧栏和迁移后出现无法辨认的同名位置。
- 创建后分组追加到用户分组末尾，之后可按既定规则拖拽排序。

## 14. 已确认：分组重命名

- 分组拥有稳定的内部 UUID；会话关联、排序和迁移均引用该 UUID，而非显示名称。
- 用户可重命名分组；重命名不会改变组内会话关联，也不会影响之后的导出、导入匹配。
- 重命名后的名称仍须去除首尾空格、非空且不与现有用户分组重名。

## 15. 已确认：自动任务、运行与原生会话的关系

自动任务采用三层模型：

```text
自动任务定义（时间、提示词序列、会话目标、权限）
        ↓ 每次触发
任务运行记录（状态、开始/结束、摘要、错误、审计）
        ↓ 仅当实际调用 Codex / Claude 时
原生会话（正常可读的用户/模型对话）
```

- 自动任务定义不是普通会话；它位于“自动任务”页面。
- 每次实际调用 AI 工具时，才创建或继续原生会话；该会话照常出现在“最近”完整时间流中，并标注“自动任务”和来源任务名称。
- 不调用 AI 的任务，或在调用 AI 前失败的任务，只保留任务运行记录，不凭空创建空会话。

自动任务第一版必须支持：

- 设置触发时间/计划；
- 预先配置一个或多个提示词；
- 多提示词序列可选择固定间隔，或等待上一提示词得到终态回复后再继续；
- 为任务选择“每次新建原生会话”或“继续指定的原生会话”；
- 为 Codex、Claude 分别选择其实际支持的 profile/权限能力；不把某个工具的命令行参数假装成另一工具同等语义的选项；
- 默认按 Codex/Claude 的原生启动与本机既有配置执行；Workbench 不额外降低或拦截用户已在原生工具中配置的权限。
- “高权限”仅表示为目标工具显式附加其实际支持的参数；Workbench 负责展示实际参数、工具差异和审计记录，不增加自己的审批门槛或全局权限限制。
- 不把某个工具的高权限命令行参数假装成另一工具同等语义的选项；不支持时明确不可选。

提示词序列模式：

| 模式 | 触发下一条提示词的时机 | Workbench 的责任 | 工具的责任 |
|---|---|---|---|
| 等待完成 | 上一条提示词对应的原生回合达到终态后 | 观察并记录终态，再提交下一条 | 正常执行原生回合 |
| 自定义固定间隔 | 自上一条提示词提交起经过用户配置的时间 | 到点即提交下一条，不人为阻止上一回合未完成时的输入；记录实际提交与最终状态 | Codex/Claude 自行处理其原生等待、排队或拒绝语义 |

固定间隔不是 Workbench 对同一会话的并发拦截策略。若工具接受输入，后续提示词可在上一回合未结束时提交；若工具等待、排队或拒绝，则界面和运行记录如实呈现该工具的结果。任务整体超时仅按用户配置的任务预算处理，不因 Workbench 人为串行化而失败。

计划表达：

- 第一版提供常用的可视化计划：一次性指定日期时间、每隔 N 分钟/小时、每天指定时刻、每周指定时刻。
- 同时提供可选的高级 Cron 输入，用于表达可视化表单无法覆盖的复杂规则。
- 两类入口最终保存为统一计划定义并由同一调度器执行；高级 Cron 不产生第二套调度机制。
- 每个任务保存一个固定 IANA 时区；创建时默认当前设备时区，用户可修改。任务迁移到其他设备后仍按保存的时区解释，不随目标设备时区漂移，并正确处理夏令时。
- 服务停机、设备休眠或调度器未运行期间错过的触发，在恢复后只记录为“已错过”，并在自动任务页和总览待处理区提示；第一版不自动补跑，用户可手动立即运行。
- 同一自动任务不允许重叠运行。若下一次计划触发时该任务上一轮仍在运行，本次记录为“因前序仍运行而跳过”；不排队补跑，也不启动第二个任务实例。

## 16. 已确认：双机本地运行与会话分叉

- 两台设备各自在本地运行不同的新会话，或各自使用同一原生会话的副本但接受分叉时，不需要持续同步。
- 若两台设备分别继续同一个原生会话副本，则从首次各自写入起视为两个独立分叉；Workbench 不承诺把它们自动合并回一个可可靠 Resume 的原生会话。
- 原因不只是 JSONL 文本顺序：两边模型回复都基于不同上下文和工具状态生成，简单拼接不能恢复单一可信的原生回合历史。
- 如果需要汇合两条分叉，用户显式选择一条作为当前会话，并以另一条的摘要或指定消息发起新的 Handoff；不修改任何原生历史。
- 只有“两台设备同时写同一个共享原生文件”或“离线分叉后希望自动汇合”为目标时，才需要实时锁、同步与冲突合并；第一版不支持这两种语义。

## 17. 已确认：远程访问所有者设备

- 第一版支持将所有者设备上的 Workbench 作为远程访问目标；另一台设备用浏览器访问其界面，查看和操作的仍是所有者设备上的同一份会话和任务。
- 所有 Codex/Claude 进程、原生会话文件、轻量索引和自动任务实际只在所有者设备上运行；远程浏览器不复制原生数据，也不在自身设备启动原生工具。
- 服务默认只监听本机。用户必须在设置中明确启用受信任局域网访问并配置认证后，其他设备才可连接；默认不暴露到公网。
- 远程端可使用完整工作台操作；审计记录保留请求来源设备信息。

## 18. 已确认：显式迁移与设备交接

迁移采用由用户显式选择范围的一次性包，而不是复制整个 Workbench 数据库：

```text
迁移包
├─ Workbench 轻量元数据
│  ├─ 分组、收件箱位置、排序
│  ├─ 自动任务定义、计划、提示词、会话目标、非敏感工具参数
│  └─ 索引与来源匹配信息
├─ 用户选定的原生 Codex / Claude 会话文件
└─ 可选：小型任务运行摘要与审计索引
```

- 默认不包含 API Key、登录态、系统凭据、完整事件投影库、缓存、临时目录或大型原始日志。
- 项目代码不属于 Workbench 迁移包，仍由 Git 或用户自己的文件迁移方案处理。
- 导入时重新扫描原生会话，并校验目标设备的工具、profile 和项目路径；无法匹配时标为“需要重新配置”，不静默改写。
- 设备交接：源设备暂停相关自动任务，并等待活动运行结束或由用户取消；导出并复制选定内容；目标设备导入、扫描和校验；用户确认后，目标设备才接管后续运行。

## 19. 已确认：重型投影库的直接清理

- 不保留现有重型投影库的长期归档、兼容读取路径或回滚副本。
- 实施迁移时，先提取仍有价值的轻量数据（例如分组、任务定义、必要的受控运行审计），并从原生 Codex/Claude 文件重建、核验新的轻量索引。
- 核验通过并切换至新索引后，直接删除可由原生文件重建的完整事件、raw JSON、会话副本、重型全文投影及旧重型库；不额外复制同等大小的数据库。
- 删除前必须向用户列明确切删除对象、预计释放空间与仍会保留的轻量数据；删除完成后报告实际释放空间。该要求是删除操作的透明性说明，不构成保留旧库或兼容模式。

## 20. 已确认：用量、订阅额度与账户余额连接器的授权和来源边界

- 所有连接器只在本机运行。凭据仅保存到操作系统凭据库，不进入 Workbench 数据库、迁移包、日志或诊断 payload。
- 仅接入厂商正式支持的查询接口或用户明确选择的本地只读数据来源；不通过网页抓取取得余额或套餐信息。
- 对 CC Switch 已支持的订阅额度，若其已安装且本机可读，Workbench 默认优先展示其只读结果，并明确标注“来源：CC Switch”；这样复用其随厂商变化维护的适配能力，不复制其完整数据。
- 用户可为同一类订阅改用自行配置的来源；来源选择是可见、可修改的设置，而不是隐式替换。
- CC Switch 未支持的厂商或数据类型，才由 Workbench 按厂商逐一查证官方文档、授权方式、刷新限制与数据口径后接入；未确认前显示“暂不支持/未连接”，不猜测数值。

## 21. 已确认：连接器刷新与失败降级

- 打开总览或用量统计时检查已连接来源；用户始终可以手动刷新。
- 服务运行期间默认每 15 分钟刷新一次；若厂商 API 或 CC Switch 的限制更严格，遵守其最小刷新间隔。
- 每项额度/余额显示数据来源和最后一次成功刷新时间。
- 刷新失败时保留上一次成功值，并标记“数据可能过期”；首次从未成功读取时显示“未连接/不可用”，绝不将未知显示为零。
- 只有余额低于用户阈值、套餐额度接近耗尽或数据长期过期时，总览才产生预警。

## 22. 已确认：首批官方连接器范围

- 首批正式连接器：DeepSeek API 账户余额、Kimi / Moonshot API 账户余额、阿里云 BSS 账户可用余额；均使用用户在 Workbench 本机凭据库中独立配置的只读授权。
- 阿里云余额使用 BSS OpenAPI 所需的 RAM/STS 只读授权，不能复用 DashScope API Key。
- OpenCode Go、GLM Coding Plan 暂无已确认的正式个人订阅用量/剩余额度查询接口；第一版明确显示“暂不支持自动读取”，不抓取网页或未文档化接口。
- CC Switch 3.18.0 虽可在自身界面展示部分订阅窗口与已启用的余额查询，但结果由其内部进程缓存提供，未发布稳定本地 API 或非敏感导出契约；Workbench 不自动读取其数据库、缓存、Tauri IPC 或凭据配置。只有未来发布稳定只读接口后，才考虑显式启用的版本化适配器。

### CC Switch 与 Workbench 的最终关系

- 两者独立运行；CC Switch 不构成 Workbench 的安装、启动或用量/余额展示依赖。
- Workbench 直接解析 Codex/Claude 原生会话，并通过自己的官方连接器读取可支持的账户余额；不复用 CC Switch 的令牌、Provider 配置、查询脚本或内部缓存。
- CC Switch 的订阅窗口和余额仍由用户在 CC Switch 自身界面查看；Workbench 可以识别其已安装并提供说明或打开入口，但不把数值伪装为自己读取的结果。
- `proxy_request_logs` / `usage_daily_rollups` 只保留为“用量统计”中 CC Switch 可选数据源卡片的只读适配候选，须有独立的 schema 探测、字段白名单和去重设计；不进入总览或默认会话 Token 统计。
- 本项目既有的“代理流量”辅助功能基于 Clash，关注网络字节、连接和网络运行状态；它与 CC Switch 的模型请求、Token、成本和延迟数据无关，不混合展示。
- 检测到 CC Switch 安装且其只读 schema 兼容时，用量统计显示独立的“CC Switch”卡片：展示其代理观测范围内的请求数、Token、已记录成本、数据覆盖范围、来源版本和最后成功读取时间；订阅窗口与余额因无稳定读取契约仅显示“由 CC Switch 管理，可打开查看”，不展示或推测数值。
- 若 CC Switch 将来发布稳定、非敏感的只读 API 或导出契约，再以用户显式启用、版本化 best-effort 适配器方式接入；读取失败立即降级为不可用。

## 23. 已确认：Cockpit Tools 仅共存、不集成

- Cockpit Tools 是独立的本地账号和多实例管理软件。其功能包括多账号切换、多实例、配额监控、唤醒任务和 Codex 会话同步；官方信息见 [README](https://github.com/jlcodes99/cockpit-tools/blob/main/README.en.md) 与 [发布说明](https://github.com/jlcodes99/cockpit-tools/releases)。
- 本机 Cockpit 数据目录包含账号、实例、配置、备份、日志和密钥相关文件。Workbench 不读取、显示、调用或写入这些内容，也不调用其 API、WebSocket、进程、会话同步、SSH 同步或账号切换功能。
- 因此“共存但不集成”在产品功能上等同于无关：Cockpit 不出现在导航、设置、会话、用量统计、自动任务或迁移流程中，也不影响 Workbench 的可用性。
- 唯一需要处理的是同一原生 Codex/Claude 文件可能被其他本地工具同时改变。Workbench 不检测 Cockpit 是否运行，而使用通用的完整记录解析、文件变更检测和来源健康度处理，不识别或依赖 Cockpit 专用格式。
- 旧的 `cockpit_profile_whitelist` 发现路径不保留为目标产品能力；额外原生目录统一由用户在 Workbench 中手动登记。
- 若多个手动登记目录出现相同工具、相同原生会话 ID 的文件，视为同一逻辑会话的多个只读来源副本。正常列表只保留一条会话并标记“多来源”，默认打开最近完整来源；路径、差异与来源切换由高级诊断抽屉按需显示。不同来源后续各自写入即为分叉，Workbench 不自动合并，跨来源继续由用户明确选定来源或使用 Handoff。
