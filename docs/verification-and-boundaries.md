# AI Coding Workbench 验证与边界手册

> 状态：已确认通用验证基线
> 更新时间：2026-08-01-21-54-08
> 创建时间：2026-07-24-04-51-45
> 适用范围：所有 Workbench Phase 的设计、实现、测试、人工验收、外部集成与交付边界
> 不包含：某个 Phase 的具体任务、测试文件清单、命令、固定覆盖率目标或实现证据

## 1. 目的与权威顺序

本文件只规定跨 Phase 都成立的验证原则、执行顺序和安全边界。它不是测试清单，也不是实现任务书。

权威顺序如下：

1. 用户的明确指示；
2. 仓库根 `AGENTS.md` 与当前目录的 `AGENTS.md`；
3. `CONTEXT.md` 的术语定义；
4. `docs/ai-coding-workbench-architecture.md` 的已确认架构与决策记录；
5. 当前 Phase 计划中的目标、任务、验收项、具体测试位置、命令和执行证据；
6. 本手册的通用验证规则。

若文件之间不一致，停止扩大实现范围，先修正文档或请用户确认；不得以旧测试、旧截图或旧 Phase 文本推翻已确认架构。

## 2. 责任分工

| 内容 | 归属位置 |
| --- | --- |

| 难以逆转的架构权衡 | `docs/adr/` |

因此，本文件禁止列出固定测试文件名、测试函数名、过期命令或某次运行结果。测试会随实现移动、拆分或删除；每个 Phase 计划必须在实施前链接到当时最新的测试目录和验收命令。

## 3. 每项工作的执行顺序

1. **确认范围**：阅读架构、术语和当前 Phase；确认该 Phase 已获用户批准。架构反馈只更新文档与计划，不自动授权代码实现。
2. **声明验证**：在对应 Phase 计划中写明要保护的行为、最新测试位置、自动化命令、人工验证和外部写入边界。
3. **最小实现**：只改已批准 Phase；不顺带重构无关模块，不开始后续 Phase。
4. **分层验证**：先运行与改动最近的测试，再运行 Phase 规定的回归；必要时进行浏览器、迁移或真实工具人工验证。
5. **安全复核**：确认未写入原生会话、第三方数据库、账户、凭据或外部软件；检查临时产物和敏感信息。
6. **记录证据**：把命令、结果、人工观察、未覆盖风险和需要用户验证的事项写回当前 Phase 计划。
7. **停在门禁**：达到该 Phase 的退出条件后等待用户验收；不得自动开始下一 Phase。

## 4. 通用正确性边界

### 4.1 范围、来源与数据质量

- 原生 Codex/Claude 会话文件是会话内容事实源。Workbench 只保存获批准的轻量索引、分组和最小运行审计，不能重新引入完整会话副本、raw 事件库或重型全文投影。
- 索引更新必须能处理追加、部分写入、文件替换、缩短、移动和暂时不可读；只解析完整记录，失败时保留上一次已知状态并说明来源健康度。
- 每个数值、状态和摘要都应有来源与质量语义。`exact`、`estimated`、`unavailable` 不可互换；未知不得被渲染为零或成功。
- 原生未知事件必须降级为可诊断的未知/raw 记录，不能使整个会话、列表或运行失败。

### 4.2 工具适配与可读 UI

- Codex、Claude 等工具私有参数和事件必须停留在 adapter 边界后；通用 API、索引和 UI 只消费规范化 DTO。
- 默认会话 UI 显示可读消息、工具摘要和明确的回合状态；原始协议只在用户主动打开的高级诊断中出现。
- 发送完成以原生工具的明确回合完成信号为准，而不是单个流式片段、单条消息完成或超时猜测。
- New、Resume 与 Handoff 必须语义准确：跨工具只能 Handoff 创建新会话，不能伪装为 Resume。

### 4.3 执行、权限与自动任务

- 用户输入不能通过拼接 shell 字符串传递；工具调用使用参数数组和 stdin/协议字段。
- 真实模型请求、账户消耗、危险权限、沙箱绕过、取消和进程终止都需要当前任务已获得的明确授权；测试不得默认消耗真实额度。
- 高权限是原生工具的显式参数映射，必须在提交前可见；Workbench 不得声称提供其没有实现的审批或隔离。
- 自动任务使用固定 IANA 时区、无自动补跑、同任务不重叠；每次调度都保留成功、失败、跳过或错过的可解释事实。

### 4.4 安全、隐私与外部系统

- 凭据、Cookie、令牌、账户响应原文和敏感路径不进入 DTO、日志、数据库、导出、截图或测试 fixture。
- 原生工具目录、CC Switch、Cockpit Tools 和其他第三方目录默认只读。外部软件和数据源是可选集成，缺失、版本不兼容或读取失败不得破坏核心会话功能。
- CC Switch 的代理请求观测只能作为用量统计的独立、非相加来源；不得读取其凭据、内部缓存、订阅窗口或余额缓存。Clash/Mihomo 网络字节与模型 Token/成本不混用。
- 默认仅本机访问；远程所有者设备模式必须有显式启用、认证、来源审计和非公开暴露边界。

### 4.5 迁移与删除

- 多设备不会后台同步或自动合并同一原生 JSONL；并行继续形成分叉，结合信息使用 Handoff。
- 迁移是显式、可确认的交接流程：暂停或结束源端任务，传输批准的轻量元数据和选择的原生文件，目标端验证来源后再接管。
- 删除旧重型投影前必须列出精确目标、预计释放空间和保留数据；完成后报告实际结果。没有获批的迁移阶段不得删除用户数据。

## 5. 测试策略

测试选择随当前 Phase 改动而定，但以下层次必须按风险组合使用：

| 层次 | 验证对象 | 典型用途 |
| --- | --- | --- |
| 单元/fixture | 解析、适配、映射、索引状态机、DTO 和权限参数 | 版本化原生事件、未知事件、部分写入和边界输入。 |
| 集成 | API、轻量索引、调度、数据库迁移或外部只读 adapter | 验证稳定合同和错误降级，不接触真实账户。 |
| 前端 | 可读消息流、导航、表单状态、可访问性、响应式布局 | 用固定 fixture 或假服务验证用户可见行为。 |
| 端到端/人工 | 原生工具协议、浏览器流程、迁移、权限、真实工具行为 | 仅在对应 Phase 和用户授权允许时执行。 |

执行前先在 `tests/ai_workbench/` 查找当前 Phase 或能力目录的最新测试；前端测试同样以当前目录结构为准。不要从本手册复制路径，也不要因为旧文件仍存在就跳过计划中要求的新验证。

## 6. 人工验收的最低问题集

每个影响用户界面的 Phase，应在计划中按改动范围回答以下问题：

- 用户能否理解当前数据来源、质量、加载/失败状态和下一步？
- 会话能否以可读内容连续阅读，并能明确判断一轮输入何时结束？
- New、Resume、Handoff、取消、权限和高风险操作是否与实际工具行为一致？
- 在无数据、来源移动、解析失败、离线、窄屏和键盘操作下，界面是否仍可使用？
- 统计、余额、订阅、代理请求观测和网络流量是否保持独立口径？
- 是否有任何写入原生文件、第三方目录、账户或真实模型调用；若有，是否已获明确授权并记录？

## 7. Phase 证据模板

以下内容应写入对应 Phase 的执行证据区，而不是本文件：

```md
### 本次验证证据

- 改动范围：……
- 保护的行为与风险：……
- 当前测试位置：……
- 自动化命令与结果：……
- 人工验证步骤与结果：……
- 外部写入/真实请求：无；或已获用户于……明确授权，范围为……
- 未覆盖项、已知限制与需要用户确认的事项：……
```

## 8. 最终自审

- [ ] 本次工作符合已批准范围，且没有跨入后续 Phase。
- [ ] 架构、术语、Phase 计划和实现没有互相矛盾。
- [ ] 具体测试位置、命令和结果已写在当前 Phase，而非本通用手册。
- [ ] 原生会话、外部软件、账户和凭据未被未授权读写或泄露。
- [ ] 数据质量、来源、错误和终态对用户可见且表述准确。
- [ ] 临时文件只在批准的产物目录中，最终差异不含本机数据或密钥。
- [ ] 已记录需要用户亲自页面验证或授权的事项，并在完成后停止于正确门禁。
