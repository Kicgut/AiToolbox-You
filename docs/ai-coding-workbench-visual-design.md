# AI 编程工作台视觉设计方案

> 状态：已确认设计基线
> 更新时间：2026-08-01-21-54-08
> 创建时间：2026-07-31-01-43-47
> 适用范围：Workbench SPA 的桌面端优先体验；覆盖总览、会话工作区、自动任务、用量统计、代理流量、设置与全局导航
> 不包含：后端数据合同变更、真实模型请求、外部工具写入、代理流量采集器或存储重写

## 1. 目标与边界

Workbench 是把 Codex、Claude 等原生工具整合为可长期使用的本地工作台，而不是再造一个模型聊天服务或运行日志查看器。界面必须让用户快速判断：正在看哪个原生会话、这次输入是否真正结束、数据来自哪里、哪些操作需要注意风险。

- 默认展示人类可读的连续对话；原始协议、诊断和审计通过按需抽屉查看。
- 原生会话文件是内容事实源。列表和组织信息来自轻量索引，不能把扫描副本伪装为原始内容。
- 不展示虚构数据：未知数值显示 `—`、状态和原因；不可用不等于 `0`。
- Codex、Claude、账户连接器和 CC Switch 都是有来源边界的数据源；工具品牌只表示来源，不表达成功、警告或失败。
- 不采用装饰性毛玻璃、厚重阴影、渐变文字或无意义动效。工作台的重点是可读性、稳定定位和可恢复操作。

## 2. 全局信息架构

默认入口是“总览”。一级导航固定为：

```text
┌──────────────────┬────────────────────────────────────────────┐
│ AI 编程工作台     │ 页面标题、说明、页面自身的操作与状态         │
│                  ├────────────────────────────────────────────┤
│  总览            │                                            │
│  会话            │              当前页面主内容                  │
│  自动任务        │                                            │
│  用量统计        │                                            │
│                  │                                            │
│ ───────────────  │                                            │
│  代理流量        │                                            │
│  设置            │                                            │
│                  │                                            │
│ ● 本地服务状态    │                                            │
└──────────────────┴────────────────────────────────────────────┘
```

| 区域 | 规则 |
| --- | --- |
| 品牌区 | 点击回到总览；收窄时保留图标和可访问名称。 |
| 主导航 | 总览、会话、自动任务、用量统计；当前项同时使用图标、文字、背景和焦点状态，不只依赖颜色。 |
| 辅助导航 | 分割线下仅放代理流量和设置。代理流量是独立 Clash/Mihomo 网络流量功能；设置承载本地偏好与连接器管理。 |
| 底部状态 | 以文字说明本地服务、来源扫描或离线状态；颜色是辅助信息。 |
| 页面顶部 | 保持页面独立的标题、说明、筛选和主要操作；不能把全局操作堆进每页。 |

“运行中心”和“运维”不再是一级页面。New、Resume、Handoff 在会话主区完成；运行状态、用量质量、来源健康度和原始诊断分别出现在最接近其语境的位置。

## 3. 视觉语言与交互基线

现有 `frontend/src/styles/tokens.css` 是实现令牌的起点。视觉以浅色、克制的开发工具界面为基调：冷灰画布、白色内容面、靛蓝主操作色和完整的语义状态色。

| 要素 | 规范 |
| --- | --- |
| 版式 | 使用 `Inter, PingFang SC, Microsoft YaHei, system-ui`；正文和标签保持紧凑、稳定的固定字号层级；数字使用 `tabular-nums`。 |
| 表面 | 页面画布、主面板、次级面板以层次和细边框区分；卡片只用于独立指标、摘要或明确可操作单元，避免卡片套卡片。 |
| 主操作 | 靛蓝只用于主要提交、当前选中和明确的可逆导航；危险动作使用文字、图标、影响说明和确认步骤。 |
| 状态 | 成功、警告、错误、信息、加载、禁用、选中均有图标与文本；不得仅用红黄绿。 |
| 动效 | 150–250ms 的透明度或位移动效只用于状态切换、抽屉和新内容提示；`prefers-reduced-motion` 下即时呈现。 |
| 图表 | 仅绘制真实、带来源的数据；图表必须配可读摘要或表格，不能是唯一信息通道。 |

每个交互组件都需要默认、悬停、键盘焦点、禁用、加载和错误状态。加载使用骨架或局部占位，不能清空已存在内容并只显示页面级转圈。

## 4. 总览

总览不是新建入口集合，也不是完整统计页；它汇总用户当下最需要处理的事实。当前实现以 `OverviewView.vue` 和 `styles.css` 为准，`总览布局.jpg` 作为视觉构图参考。顶部保留现有右上角控制区域，不额外创造第二套全局工具栏。

### 4.1 总览页的视觉定位

总览应像一块“冷色玻璃工作台”：背景安静、内容分层清楚、重点数字和可操作入口立即可见。玻璃效果服务于层级，不作为装饰主题；任何数据、状态和动作都必须先保证可读性，再使用透明度、模糊和阴影。

整体构图固定为：

```text
┌────────────────────────────────────────────────────────────────────┐
│ 品牌/问候/页面说明                              全局搜索  通知  用户 │
├──────────────┬──────────────┬──────────────┬────────────────────────┤
│ 最近会话      │ 已记录请求   │ 运行中/待处理 │ 数据质量记录            │  ← 指标卡
├──────────────────────────────────────────────┬─────────────────────┤
│ 真实数据摘要 / 用量趋势                       │ 运行队列              │  ← 主展示栏
├───────────────────────────────┬──────────────┴─────────────────────┤
│ 最近会话                        │ 实时运行          │ 数据质量          │  ← 信息栏
└───────────────────────────────┴───────────────────┴─────────────────┘
```

- 第一层四张等宽指标卡是扫描入口，不是复杂图表。每张卡只表达一个事实：图标、标签、主值、数据来源/质量说明；未知值使用 `—`，不能用 `0` 填充。
- 第二层是主信息区。左侧约占 2/3，承载真实数据摘要或趋势；右侧约占 1/3，承载运行队列。主展示栏允许留白，空状态必须解释数据为什么暂不可用以及下一步去哪里查看。
- 第三层是三个等宽信息栏：最近会话、实时运行、数据质量。行项目是轻量可点击单元，点击进入对应工作区；它们不复制完整页面内容。
- “查看统计”“查看全部”“打开运行中心”等链接使用统一的靛蓝文字动作，不再单独创建一条全局操作栏。

### 4.2 配色与层级令牌

以下令牌与现有 `tokens.css`、总览页实际 CSS 保持一致；如果局部样式出现不同值，以这组语义令牌为准：

| 层级 | 颜色/效果 | 用途 |
| --- | --- | --- |
| 工作台背景 | `#f6f7fb` | 页面底色，低对比冷灰蓝；可叠加极弱的冷色环境光，但不能形成明显渐变背景 |
| 主文字 | `#172033` | 标题、主数值、关键实体 |
| 次文字 | `#647087` | 说明、来源、时间、空状态解释 |
| 弱文字 | `#8a94a6` | 辅助元数据、禁用文案 |
| 唯一主强调色 | `#6366f1` | 图标、链接、选中指示、主要焦点；避免同时引入第二个高饱和品牌色 |
| 强调浅底 | `#eeefff` | 选中导航、图标底、轻量提示 |
| 辅助强调色 | `#9b8fa8` | 莫兰迪紫灰；用于次级分组、来源/索引信息、辅助图标和非关键 hover |
| 辅助强调深色 | `#75667f` | 辅助强调色的文字、细线和需要更高对比度的图标 |
| 辅助强调浅底 | `#eeeaf1` | 次级标签、辅助状态块和低干扰背景提示 |
| 玻璃表面 | `rgba(226, 233, 245, .38)` | 卡片、展示栏和主要工作区表面 |
| 玻璃边界 | `rgba(255, 255, 255, .82)` | 1px 高光边界，帮助透明表面与背景分离 |
| 成功状态 | `#087443` | 已完成、健康、精确等正向事实；必须配文字或图标 |
| 危险状态 | `#b42318` | 失败、不可用、风险；不依赖红色单独传达含义 |

主文字与次文字的对比度优先级高于玻璃通透度。卡片内容区使用不透明度较高的冷色填充；列表行可以更透明，但正文、状态和数字不应透过背景纹理而失焦。

莫兰迪紫灰是辅助强调色，不是第二套主品牌色。靛蓝继续负责主要操作、当前导航、选中状态和键盘焦点；莫兰迪紫只负责次级信息的分组和氛围层。它可以让冷灰蓝工作台增加一点温度，但不能改变用户对“什么最重要”的判断。

建议实现为以下令牌：

```css
--color-accent-secondary: #9b8fa8;
--color-accent-secondary-strong: #75667f;
--color-accent-secondary-soft: #eeeaf1;
```

- 可用于来源/索引信息、辅助图标、空状态插图、次级展示栏边界、低优先级标签和非关键 hover 高光。
- 在玻璃表面上使用低透明度叠加，例如 `rgba(155, 143, 168, .14)` 的背景和 `rgba(155, 143, 168, .28)` 的边界。
- `#9b8fa8` 适合图标、边框和背景，不直接用于小字号正文；正文或需要更高对比度的文字使用 `#75667f`。
- 不用于成功、错误、警告等语义状态，也不用于替换主操作的靛蓝色。
- 不把靛蓝与莫兰迪紫做成大面积渐变；辅助色在一屏中的视觉占比控制在约 15%–25%，只作为层次提示。

### 4.3 卡片、展示栏与毛玻璃规则

- 指标卡和展示栏统一使用 `16px` 圆角、`1px` 高光边界和约 `18px` 内间距；卡片之间使用 `14px` 间距，保持参考图中的整齐网格。
- 主展示栏与指标卡使用同一玻璃材质，不通过不同颜色制造页面碎片化；尺寸和位置表达信息权重，颜色只表达状态与动作。
- 推荐的统一玻璃参数是：`background: rgba(226, 233, 245, .38)`、`border: 1px solid rgba(255,255,255,.82)`、`backdrop-filter: blur(30px) saturate(1.25)`，配合轻微外阴影和 `inset 0 1px 0 rgba(255,255,255,.65)` 高光。
- 卡片内部的列表行、质量条和状态块使用更浅的半透明层（约 `rgba(239,244,252,.34)`），不能再套一层厚重阴影；列表行只需要细边界和 hover 提升。
- 毛玻璃必须有明确的实色降级：当浏览器不支持 `backdrop-filter`、用户启用减少透明度或背景对比不足时，回退到 `#ffffff` / `#f0f2f7`，布局和信息不变。
- 禁止把毛玻璃用于长篇正文、密集表格或需要持续阅读的代码/日志区域；这些区域应使用更高不透明度的内容面。

### 4.4 鼠标悬浮、选中与键盘焦点

交互层级遵循“悬浮提示、选中定位、点击进入”的顺序：

- 卡片 hover：在 `160ms` 内轻微上移 `2–3px`，边界向靛蓝偏移，阴影略增强，表面变亮；不改变布局、不放大内容、不持续闪烁。指标卡 hover 只强调可关联性，不伪装成按钮。
- 可点击行 hover：显示浅靛蓝背景、靛蓝边界和轻微上移；标题保持原有截断规则，不能因为悬浮而撑开网格。
- 选中态：使用靛蓝边界或左侧 `3px` 内嵌指示条，加上浅靛蓝底；不能只靠阴影或颜色深浅表达。总览通常没有持久选中项，进入详情页后由目标页面保持选中。
- `:focus-visible`：使用 `2px` 以上靛蓝焦点环并保留 `2px` 间距，键盘焦点不能被透明边界或阴影吞掉。
- 禁用态：降低对比度并保留原因文案；不执行 hover 上移，也不显示“可点击”的手势。
- `prefers-reduced-motion: reduce` 下取消位移和过渡，只保留立即出现的颜色/边界变化。

### 4.5 悬浮详情的展示逻辑

悬浮详情用于补充信息，不替代卡片主信息，也不承担唯一可访问入口：

- 对指标卡：悬浮或键盘聚焦后展示一个轻量说明层，内容依次为“数据口径、来源、最近成功时间、质量/不可用原因、可跳转页面”。没有额外事实时不显示空 tooltip。
- 对运行队列和最近会话行：悬浮详情展示完整标题、工作目录、工具/profile、最近更新时间、事件数或运行状态；列表中的主标题仍保持单行截断。
- 对数据质量条：悬浮详情展示质量标签、来源和计数；不能只显示颜色条。
- 详情层应在目标元素附近定位，避免遮挡同一栏的其他关键操作；视口边缘自动翻转，最大宽度约 `320px`，正文可换行。
- 详情层通过 `aria-describedby` 或等价语义关联，键盘聚焦时同样出现；移动端没有 hover，因此点击/聚焦或明确的“详情”入口必须提供相同信息。
- 如果详情包含操作（例如“查看统计”），使用可聚焦的 popover/面板而不是纯 tooltip；点击外部、按 `Escape` 或离开当前实体时关闭。

### 4.6 真实性、空状态与不可用状态

- 第一层四张等宽统计块分别链接至对应的会话、套餐或账户来源说明；不把不同口径相加。
- “待处理事项”是可执行或可解释的列表，不显示为了填满页面而编造的通知。
- 最近会话采用轻量行列表，点击进入会话工作区；本地数据源状态说明原生来源、轻量索引和最近扫描时间。
- 当统计、余额或订阅不可用时，保留卡片位置并显示 `—`、来源、最近成功时间、不可用原因和跳转路径。
- 趋势区域没有真实序列时，显示“暂无可绘制数据”的图标与解释，不绘制假折线、不用示例百分比替代。

## 5. 会话工作区

会话页是日常使用的核心，固定为“全局导航 | 会话上下文列表 | 对话主区”。高级诊断为右侧按需抽屉，不占用默认阅读宽度。

```text
┌──────────┬──────────────────────────┬─────────────────────────────────────┐
│ 全局导航 │ [+ 新建] 搜索 / 筛选      │ 会话标题 · Codex / Claude · 来源状态 │
│          │                          │                                     │
│          │ 分组                     │ 用户消息                            │
│          │   项目 A                 │ 模型回复                            │
│          │   项目 B                 │ 工具活动摘要〔展开〕                │
│          │ 收件箱                   │                                     │
│          │ 最近（完整时间线）        │ 输入框：New / Resume / Handoff      │
└──────────┴──────────────────────────┴─────────────────────────────────────┘
```

### 5.1 会话上下文列表

- `最近` 包含未在用户分组或收件箱中的所有会话，并按原生最后活动时间连续排列，不是最近 N 条。
- `收件箱` 是用户主动常驻的位置；解除常驻后会话按原时间回到最近，不代表删除或未读。
- V1 每个会话只允许一个主分组；分组可新建、重命名、拖动排序，删除分组前解释会话会回到最近。
- 每个会话行展示首次用户输入首行生成的标题、最近可读摘要、工具标识、活动时间和必要的来源异常。标题约 48–60 字，摘要约 80–120 字，超长内容截断而不覆盖原文。
- 搜索、筛选、分组和手动刷新位于列表栏。全文命中来自原生文件按需扫描，列表结果必须说明检索范围与进行状态。

### 5.2 可读消息流

- 主区默认显示最新约 50 组用户/模型消息；继续向上滚动才从原生文件读取更早内容。
- 同一原生回合的流式 delta 聚合为一条模型回复。只有收到原生回合完成信号才把输入从“生成中”改为“已完成”。
- 工具活动在对话中显示安全的一行摘要，可展开查看适合普通使用者的参数、结果和错误；原始 JSON-RPC/协议记录只在高级诊断抽屉中出现。
- 读取失败、来源移动、索引落后或未知事件要明确说明影响与可执行的重试/刷新动作，不能把空白误呈现为没有历史。
- 用户在底部时可跟随新内容；向上阅读时暂停自动滚动，并显示“有 N 条新内容”的可点击提示。

### 5.3 输入与动作

| 当前上下文 | 默认动作 | 视觉与行为 |
| --- | --- | --- |
| 未选择会话 | New | 选择工具和原生 profile；创建新原生会话。 |
| 选择同工具会话 | Resume | 清楚显示将继续的工具和原生会话；等待原生回合完成才解除发送中状态。 |
| 切换工具 | Handoff | 要求选择传递的消息或摘要，在目标工具中新建会话；禁止标为 Resume。 |

输入区始终显示工具、profile、权限参数和预算/时限摘要。高权限只是工具参数映射，必须显示实际影响；不能生成 Workbench 自己的虚假审批层。取消、失败、原生审批和终态在当前会话内呈现，并保留进入高级诊断的入口。

## 6. 自动任务

自动任务页服务于可重复工作，不伪装为即时聊天。页面围绕“任务定义 → 任务运行 →（如发生调用）原生会话”组织。

- 顶部提供新建任务和时区说明；列表展示启用状态、下次运行、上次结果、当前运行与来源工具。
- 任务详情使用分段表单：日程（一次、间隔、每日、每周、Cron）、固定 IANA 时区、提示词序列、New/Resume 目标、权限参数和并发规则。
- 多提示词明确显示“等待上一回合终态”或“固定间隔提交”两种模式。固定间隔不承诺工具一定并行执行。
- 运行历史是紧凑表格；真实对话通过链接打开对应原生会话。失败、跳过、错过和等待都必须说明原因与下一步。
- 同一任务不重叠：新触发被跳过时显示为事实记录，而非静默丢失。

## 7. 用量统计

用量统计统一展示不同口径，但绝不混算。

```text
筛选：时间范围 · 工具 · 模型 · Provider · 数据来源

会话观测 Token | 代理请求观测 | 订阅窗口 | API 账户余额

主趋势 / 拆分表                              数据来源与质量
官方连接器状态                                CC Switch（可选）卡片
```

- 会话观测 Token 是默认会话用量口径；代理请求观测可能重叠，必须独立标示为不可相加来源。
- 账户余额和订阅窗口分别显示来源、最后成功时间、刷新状态、预警阈值和“不可用”原因。
- 官方余额连接器按账户/平台维度显示；凭据、令牌和原始响应不进入页面、日志或导出。
- 检测到兼容的 CC Switch 时才显示可选卡片。它只呈现公开、稳定且非敏感的代理请求观测、版本、覆盖范围与最近读取状态；不读取或展示内部订阅窗口、余额缓存或凭据。
- 无值、过期、部分失败与全部失败采用不同文案，不以零值图表代替。

## 8. 代理流量与设置

### 8.1 代理流量

`代理流量` 是辅助页面，只展示 Clash/Mihomo 的网络字节、连接、域名和采集器状态。它不展示模型 Token、成本、模型请求或 CC Switch 数据。

- 页面结构为范围筛选、流量摘要、趋势、排行、实时连接和采集器状态。
- 代理/直连、上传/下载使用固定图例、文字和图标区分；所有导出遵循当前筛选范围。
- 断线、重连、数据滞后、空数据和采集失败有独立状态，并不影响会话和用量页面。

### 8.2 设置

设置是本地偏好和连接器控制面：索引与扫描偏好、数据保留、来源状态、账户连接器、迁移导入导出和界面偏好。危险或不可逆的操作必须说明保留/删除范围、预计影响和确认方式；不把原始凭据回显给用户。

## 9. 组件与状态边界

| 组件 | 责任 |
| --- | --- |
| `AppShell` / `SideNav` | 全局导航、辅助导航、服务状态和响应式收纳。 |

## 10. 响应式与可访问性

- 宽屏（≥1280px）完整显示会话列表和可选诊断抽屉；主消息栏保持舒适阅读宽度。
- 中屏（768–1279px）侧栏可收窄，诊断抽屉覆盖式打开；会话列表仍可见。
- 窄屏（<768px）导航、会话列表和诊断均为分步抽屉；主要发送、取消和确认目标至少 44px。
- 所有页面有跳过导航链接、可见 `:focus-visible`、语义化按钮/链接、标签关联和图标按钮的可访问名称。
- `aria-live` 仅播报终态、审批、错误和新内容数量，绝不逐 token 播报模型文本。
- 键盘可完成导航、搜索、选择会话、展开工具摘要、发送/取消、打开诊断和处理确认操作。

## 11. 实施与验收原则

视觉实现必须先匹配当前架构和已批准计划，不能因为本文件存在就直接开始新 Phase。实施顺序由相关 Phase 计划定义；本文件只提供跨页面的界面基线。

- 先建立/复用设计令牌和共享壳层，再迁移页面；避免每页自建导航和状态样式。
- 先保证事实与状态正确，再增加图表、动效或高密度交互。
- 页面变更不得写入原生会话、第三方数据库、账户或配置，也不得绕过真实模型执行门禁。
- 验收至少覆盖桌面三栏、窄屏抽屉、键盘焦点、无数据/失败/加载/终态、来源质量和减少动态效果。具体测试任务、文件和命令写入对应 Phase 计划。
