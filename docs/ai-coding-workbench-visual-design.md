# AI 编程工作台视觉设计方案

> 状态：待审查设计提案
> 创建日期：2026-07-31
> 适用范围：Workbench SPA 的桌面端优先体验；覆盖总览、会话中心、运行中心、用量统计及全局导航
> 不包含：后端数据合同变更、真实模型请求、外部工具写入、代理流量功能重写

## 1. 目标

将 AI 编程工作台从“多个技术页面的集合”提升为可长期使用的本地开发工作台。视觉应帮助用户在数秒内回答四个问题：

1. 当前位于哪个功能区？
2. 最近的会话、运行和数据状态是什么？
3. 哪些操作可立即执行，哪些功能仍未开放？
4. 当前操作是否涉及等待、审批、失败或风险？

本方案借鉴参考图的浅色画布、留白、圆角卡片、图标化指标和层级清晰的侧栏，但不复制任何第三方品牌、内容或具体界面。

## 2. 不可突破的产品边界

- 继续使用 Vue 3、TypeScript、Vite、Vue Router、Pinia；构建产物仍随 FastAPI 发布，生产机器不依赖 Node.js。
- 统计指标必须保留 `exact`、`estimated`、`unavailable` 的来源与质量含义；不可用数据不能伪装为 `0`，也不能展示虚构趋势。
- 运行中心只呈现服务端已确认的 run、事件、审批和能力；前端不能声称支持后端无法执行的模型、权限或动作。
- Codex、Claude、CC Switch、Cockpit Tools 的具体行为仍由适配器和后端合同决定；视觉层不得依赖原始外部事件结构。
- 代理流量监控保持独立辅助功能，侧栏只提供入口，不在本次方案中重写其实现。
- 总览页维持“功能入口优先”的既有决定。KPI、图表和数据质量的完整展示属于用量统计页；总览只可展示不冒充统计事实的产品状态与功能入口。

## 3. 信息架构与导航

桌面端使用固定左侧应用导航，替代当前顶部横向导航。它提供稳定的空间定位，而页面自己的筛选、列表和详情留在内容工作区中。

```text
┌──────────────────────┬──────────────────────────────────────────┐
│ 品牌 / 工作台状态     │ 页面标题、上下文说明、页面级主要操作      │
│                      ├──────────────────────────────────────────┤
│ 总览                 │ 页面主体：卡片、表格、图表、时间线或详情   │
│ 会话中心             │                                          │
│ 运行中心             │                                          │
│ 用量统计             │                                          │
│ ───────────────────  │                                          │
│ 代理流量             │                                          │
│ 自动任务（未开放）   │                                          │
│ 设置（未开放）       │                                          │
│                      │                                          │
│ ● 本地运行中         │                                          │
└──────────────────────┴──────────────────────────────────────────┘
```

| 区域 | 目的 | 交互规则 |
|---|---|---|
| 品牌区 | 显示工作台名称；侧栏收起时保留图形标识 | 点击回到总览 |
| 主导航 | 总览、会话中心、运行中心、用量统计 | 当前项有文字、图标、背景和左侧指示条四重状态，不只依赖颜色 |
| 辅助功能区 | 代理流量、未来自动任务、设置 | 未开放项禁用且解释对应 Phase，不能伪装为可点击入口 |
| 底部状态 | 本地服务、连接状态、版本或快捷设置 | 红/黄/绿之外必须同时有文字说明 |

建议新增独立的“运行中心”路由。会话中心中的 Resume/Fork 操作可携带当前会话上下文跳转至该页面；不再将运行编辑器、运行列表和实时流永久堆叠在会话时间线底部。

## 4. 视觉语言

### 4.1 气质

采用轻盈、克制、可信的开发工具气质：浅灰蓝背景、白色主要表面、靛蓝为主要操作色，配以少量绿色、琥珀色和红色表达状态。卡片以排版和留白组织信息，不使用厚重阴影、过量渐变或玻璃拟态。

### 4.2 设计令牌

| 类别 | 建议 |
|---|---|
| 画布 | `#F6F7FB`，避免纯白大面积刺眼背景 |
| 表面 | `#FFFFFF` 主卡片；`#F0F2F7` 次级面板 |
| 主色 | 靛蓝 `#6366F1`；hover 使用更深色，不以光晕代替反馈 |
| 文字 | 主文字深蓝灰；辅助文本降低饱和度但保持 WCAG AA 对比度 |
| 状态 | 成功绿、警告琥珀、错误红、信息蓝；每种都有图标与文字 |
| 圆角 | 控件 10px；卡片 16px；避免同屏混用过多圆角尺度 |
| 阴影 | 仅悬浮面板和可点击卡片使用低扩散阴影 |
| 排版 | `Inter, PingFang SC, Microsoft YaHei, sans-serif`；数字使用 `tabular-nums` |
| 动效 | 只动画 `opacity` 与 `transform`，140–180ms；尊重 `prefers-reduced-motion` |

### 4.3 图标与图表

- 图标库推荐 `lucide-vue-next`。导航图标为统一线性风格，指标卡图标置于 40px 的浅色圆角底座中。
- ECharts 只在统计页按需加载，用于真实趋势、分布与质量图。每张图同时提供可读表格或摘要，避免图表成为唯一信息来源。
- 不使用工具品牌色表达成功、警告或失败；Codex/Claude 标识仅说明来源工具。

## 5. 页面规格

### 5.1 总览

总览是导航入口，不是伪统计仪表盘。

- 顶部：欢迎语、简短产品说明、全局搜索入口（仅在真实能力可用时显示）、“新建运行”主要按钮。
- 主体：会话中心、运行中心、用量统计、代理流量、自动任务、设置的功能卡。每张卡包含图标、可用性、描述和明确 CTA。
- 产品状态：可以显示“本地服务已连接”“统计数据待加载”等非数值状态，不显示未经统计页确认的 Token、成本或趋势。
- 未开放功能：使用柔和禁用表面、Phase 标签和说明，不显示虚构数字。

### 5.2 会话中心

会话中心采用“应用侧栏 + 会话列表 + 内容主栏 + 可收起检查器”的层级，而非嵌套卡片。

```text
应用侧栏 | 会话筛选与列表 | 会话标题、筛选摘要、结构化时间线 | 检查器抽屉
```

- 会话列表栏：工具筛选、搜索、扫描动作、Profile 健康状态和虚拟化会话列表。搜索框与手动目录输入必须有可见标签。
- 主栏：标题、工具、更新时间、分叉状态和结构化事件时间线。用户/助手消息、工具调用、命令输出、文件变更和 unknown 事件采用不同但可访问的视觉类型。
- 检查器：默认在宽屏显示；中等屏幕作为右侧抽屉；包含 Session ID、Profile、Transcript、事件数、副本和差异摘要。
- Resume/Fork：只在已选中且后端能力允许的会话上显示，点击进入运行中心的预填 Composer。

### 5.3 运行中心

运行中心是 Phase 3 的受控执行界面，重点是“事实可见、风险可辨、状态可恢复”。

```text
应用侧栏 | Run 队列（分组） | 结构化运行流 / 工具活动 / 诊断 | 审计与审批详情
```

- 顶部 Composer：工具、动作、Profile、cwd、模型、权限、预算与提交摘要。默认只读策略必须始终可见；危险权限只能在用户明确选择后出现。
- 队列：分组显示 queued、active、waiting approval、recent terminal；每行包含 action、工具、Profile、工作目录简称、模型、时长、待审批数和最新事件摘要。
- 主内容：以标签页区分“对话”“工具活动”“诊断”“审计”。不以原始 JSON 作为默认阅读面。
- 审批：突出显示请求目标、风险、影响范围和“批准 / 拒绝 / 取消”操作；状态必须包含文字，不只改变颜色。
- 实时流：用户停留在底部时自动跟随；向上阅读历史时暂停自动滚动并显示新事件数量；刷新后按事件 cursor 恢复。
- 终态：成功、失败、已取消、中断、等待审批和离线均有不同文案、图标和下一步。

### 5.4 用量统计

- 顶部常驻筛选：日期、工具、Profile、项目、模型、Provider、数据来源。
- 第一行 KPI：Token、Turn、估算/实际成本、缓存命中、完成率；每张卡可展开数据来源与质量。
- 主趋势：一张主图，按需切换 token、成本或请求；不要在同一屏堆叠多张难以比较的折线图。
- 辅助区：工具/模型/项目拆分表、可靠性卡、精确/估算/不可用比例。
- 空状态：说明是“尚无数据”“正在重建”还是“连接器不可用”，并给出下一步，不显示零值图表。

## 6. 可复用组件边界

| 组件 | 职责 |
|---|---|
| `AppShell` | 侧栏、页面内容区、响应式布局与跳过导航链接 |
| `SideNav` | 导航项、可用性、收起模式、本地服务状态 |
| `PageHeader` | 标题、说明、面包屑或页面级主要操作 |
| `SurfaceCard` | 统一表面、边框、圆角、padding；不承担业务语义 |
| `MetricCard` | 图标、值、趋势、质量标签、来源展开 |
| `StatusBadge` | 文本、图标、颜色三者一致的状态呈现 |
| `EmptyState` | 原因、影响、下一步 CTA；区分无数据与错误 |
| `DataQualityBadge` | 精确、估算、不可用及其来源解释 |
| `RunRow` / `RunDetail` | 对应 P3-09 的可聚焦运行条目与四区详情 |

组件只能依赖稳定的 Workbench DTO。原始 payload 保留在显式“原始记录”区域，禁止被卡片和列表直接解释。

## 7. 响应式与可访问性

- 宽屏（≥1280px）：完整侧栏；会话中心和运行中心可显示右侧检查器。
- 中屏（768–1279px）：侧栏可收起；检查器改为可关闭抽屉；列表保留但可压缩。
- 窄屏（<768px）：侧栏成为抽屉；会话筛选与详情分步显示；主要提交与审批操作保持 44px 触控目标。
- 提供跳过导航链接、可见 `:focus-visible` 焦点、语义化 button/link、标签关联、图标按钮 `aria-label`。
- `aria-live` 只播报运行状态、审批和错误，不播报逐 token 文本。
- 使用键盘可完成：导航、筛选、选择会话、查看检查器、提交运行、处理审批、切换运行详情。

## 8. 实施与验证顺序

1. 扩展 design tokens；建立 `AppShell`、侧栏和基础状态组件，不改变后端合同。
2. 将全局导航迁移为左侧栏，并保持现有 `/`、`/sessions`、`/statistics` 与 `/traffic` 可访问。
3. 重构会话中心布局，保留虚拟列表、搜索、检查器和现有 API 行为。
4. 在 P3-09 范围内建立独立运行中心路由与可访问 Composer、队列、详情区域。
5. 重构统计页的指标、筛选、趋势与质量展示；按需引入图表库。
6. 运行前端 build、现有 Python 测试和 fake CLI 浏览器 E2E；截图、trace 和临时数据只写入 `.artifacts/` 指定目录。

## 9. 验收标准

- 用户在任意页面都能通过侧栏辨认当前位置，并在两次操作内到达会话、运行、统计和代理流量入口。
- 会话中心、运行中心在 1280px 宽度下无横向溢出；窄屏时抽屉和主要操作可用。
- 所有状态同时使用文字、图标与颜色；图标按钮、表单控件和危险操作满足可访问性交互要求。
- 无数据、请求失败、等待审批、取消中、断线与终态均有与事实一致的独立视觉状态。
- 统计图表只使用 API 已返回的数据，并保留质量和来源说明。
- 页面视觉变化不修改原生会话、第三方数据库、账户、配置或真实模型执行门禁。

## 10. 本次视觉稿的定位

生成的总览、会话中心和运行中心效果图是设计沟通材料，不是产品测试证据，也不代表其中的数字、模型、会话或运行已经真实存在。实现前应以本方案、架构文档和当前 Phase 3 的 API/能力合同为准。
