# Generated artifact and temporary-file policy

## Purpose

Development and phase verification must not scatter databases, screenshots, scripts, logs, generated schemas, or pytest directories across the repository. All disposable repository-local output uses one top-level root: `.artifacts/`.

## Allowed locations

| Output | Location | Retention |
|---|---|---|
| Pytest basetemp, temporary DBs, generated helper scripts/schemas | `.artifacts/tmp/<task-or-run>/` | Delete after verification |
| Screenshots, JSONL output, test summaries and short-lived audit evidence | `.artifacts/verification/<task-or-run>/` | Keep only while actively needed |
| Stable test fixtures | `tests/fixtures/<area>/` | Source controlled |
| Built frontend shipped with FastAPI | `app/static/workbench/` | Source controlled/generated by build |
| Application runtime data | `data/` | Local and ignored; never treat as test scratch |

## Required behavior

1. Tests use pytest `tmp_path` or `tmp_path_factory` by default.
2. A manual pytest run that needs repository-local basetemp uses `.artifacts/tmp/pytest/<unique-run-id>`.
3. A diagnostic script is committed under `scripts/` only when reusable; otherwise it lives under `.artifacts/tmp/<task>/` and is removed after use.
4. Screenshots and raw command/model output never go in the repository root. If temporarily retained, place them under `.artifacts/verification/<task>/`.
5. Do not create new top-level names such as `pytest-temp`, `verification-temp`, `codex-test-*`, `phase*-temp`, `run-temp`, or `.tmp-smoke*.db`.
6. Before handoff, run `git status --short`, remove disposable artifacts, and confirm no real transcript, credential, runtime database, local setting, cache, or virtual environment is staged.

## Cleanup boundary

Cleanup may remove only files clearly produced by tests or verification. It must not remove `data/`, `.venv/`, source fixtures, generated shipping assets, or real Codex/Claude/CC Switch/Cockpit data outside this repository. When provenance is uncertain, inspect first and preserve the file.
