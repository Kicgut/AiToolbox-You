## fastapi 路由托管策略

受约束的 catch-all（Codex 推荐）——不是"任何请求都兜底返回 index.html"，而是：

- 具体路由优先注册：/api/*、/static、/ws/*、/traffic（连同子路径）都在前面拦截掉。
- SPA fallback 放最后，且只对 GET/HEAD 且 Accept 包含 text/html 的请求生效。
- 带文件扩展名的未知路径（favicon.ico、assets/missing.js）照样走真实 404，不返回 index.html。
- 前缀按完整路径段匹配，避免 /apiary 这类误伤合法 SPA 路径的情况。

## 远程访问认证与多用户边界

FastAPI 永远只监听 127.0.0.1，不建认证系统。远程访问靠 SSH 本地端口转发，认证/加密全交 SSH。Phase 3-5 上线后 SSH 进来的人拥有实例全部权限。
完全不支持远程访问——安全边界最小，FastAPI 永远只监听 127.0.0.1。代价是离开开发机就看不了运行状态和历史会话。

## 按"主产品 + 小型辅助功能"这个新框架

顶层结构反转：仓库根直接就是 AI Coding Workbench 的工程根（app/、frontend/、tests/ 都挪到根目录）,不再套一层 products/ 或 ai-coding-workbench/ 包装。代理流量监控降级成 features/proxy-traffic-monitor/——一个"挂载在主产品上、边界清晰的辅助功能"，暴露 router + 生命周期接口给主 app 显式注册,不是并入 app/ai_workbench。

未来新增辅助功能的标准模板：统一放 features/<slug>/，每个功能自带 README。提供三种技术栈无关的集成模式：

- A. Python 进程内模块（暴露 router + 生命周期接口）
- B. 静态子应用（自建前端工具链,只把构建产物交给主 FastAPI）
- C. 本地独立进程（非 Python 或依赖冲突场景,主壳只负责启动链接和状态展示）

  ## 启动方式：

  1. Workbench 后端通过 subprocess.Popen 启动真实的：

     codex.exe app-server --stdio

  2. 不会打开可见终端窗口，而是通过 stdin/stdout/stderr 管道通信。
  3. Workbench 发送 JSON-RPC：

     initialize
     thread/resume
     turn/start

  4. Codex 的事件通过 stdout JSONL 返回，Workbench 持续解析并写入 SQLite。
  5. 启动进程后，Coordinator 开启 180 秒计时器。
  6. 如果超时仍未收到 turn/completed，会：

     turn/interrupt
     → 请求终止进程树
     → 标记为 timeout/failed

  7. Windows 下进程由 Job Object 管理，子进程也会被纳入清理范围。

  因此，这是“真实后台 Codex App Server 进程 + JSON-RPC stdio 通信”，不是模拟终端输入。修复后请重启服务，再新建一次 Resume 验证。回归测试目前为 110 passed。

 ## 会话中心的“扫描”主要是建立本项目数据库中的本地索引/规范化投影，不会复制一份新的 Codex/Claude 原生会话文件。

  ### 实际流程

  Codex/Claude 原生 JSONL 文件
          │
          │ 只读扫描
          ▼
  解析、规范化、脱敏
          │
          ├─ session_copies：会话元数据和来源路径
          ├─ events：结构化事件、文本和原始 JSON
          ├─ source_checkpoints：文件大小、mtime、解析偏移
          └─ usage_records / observations：用量事实

  ### 是否复制文件

  不会复制原始 transcript 文件：

  - 原生文件仍保留在 Codex/Claude 原目录；
  - Workbench 只保存 transcript_path；
  - 不修改原文件；
  ### 增加多少数据

  取决于扫描到的事件数量和事件内容：

   情况                                数据增长
  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
